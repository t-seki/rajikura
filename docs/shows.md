## 作り方

番組・毎週の予約・1 回の予約・キーワードは DB にあり、Web UI の番組表・番組・キーワードの画面で作る（[web-ui.md](web-ui.md)）。スクリプトや AI は、API トークンで番組の API とキーワードの API を呼ぶ（[api.md](api.md)）。下の表のキーは、その API の JSON のキー。

番組・予約・キーワードを変えると、次の番組表の同期を待たずに、すぐにジョブに展開する（[recording.md の「番組を変えた直後の展開」](recording.md#番組を変えた直後の展開)）。

## 番組

| キー | 内容 | 既定 |
| --- | --- | --- |
| `name` | 番組の名前（保存先のフォルダ名）。番組を識別するキー。書き方は下の「番組の名前の付け方」 | （必須） |
| `enabled` | 有効か。`false` にすると無効な番組になる（下の「無効な番組」） | `true` |
| `split` | 分割番組の設定（[ADR 0003](adr/0003-job-per-show-and-broadcast-day.md)）。`"none"`（分割番組でない）・`"join"`（分割番組で、パートを連結して 1 ファイルにする）・`"separate"`（分割番組で、パートごとに別のファイルにする）のどれか | `"none"` |
| `check_title` | 番組名の確かめをするか（下の「[番組名の確かめ](#番組名の確かめ)」）。放送回の番組名が週ごとに変わる番組では `false` にする | `true` |
| `weekly` | 毎週の予約の並び（下の「[毎週の予約](#毎週の予約)」）。0 個でもよい（1 回の予約だけを持つ番組） | `[]` |

分割番組は、1 回の放送が、番組表で同じ放送日の複数の放送回に分かれて載る番組。連結するのは `"join"` だけで、`"none"` の番組に同じ放送日の放送回が 2 つ以上当たっても、放送回ごとに別のファイル（パート）にする。

### 無効な番組

- 番組と予約は消さずに残し、予約（毎週の予約も 1 回の予約も）を放送回に当てない。新しいジョブはできない。
- 無効にしたときの録音予定のジョブは消える。`retrying` など録音予定のほかのジョブは残る。
- 有効に戻すと、今日から先の放送回のジョブができる。今日より前の放送回は、開始日を持つ毎週の予約なら開始日から、まだ録れる放送回のジョブができる。

### 番組の名前の付け方

[ADR 0006](adr/0006-show-name-from-radiko.md) のとおり、`name` には、radiko の番組表の番組名を原文どおりに写す。空白・記号・スポンサー名も残す。

- 落とすのは、番組名の末尾の `(1)` や `10時～11時` のような印と、放送回ごとに変わる副題（`feat. …` など）だけ。
- 番組表の「この回を録音」と[キーワード](#キーワード)が番組を作るときは、番組名から末尾の印を落とした名前で作る（作った番組の名前は人が後から直せる）。 <!-- glossary-ok: 回 -->
- フォルダ名とファイル名では、Windows で使えない文字（`<>:"/\|?*` と制御文字）が `_` に置き換わる。`album` のタグは原文のまま。
- 整えた名前が 219 バイトを超えると、末尾に `…` を付けて 219 バイト以内に切り詰める（局名も同じ。ext4 のファイル名の上限 255 バイトから、保存中の一時ファイルの名前の分を引いた値）。番組の名前と `album` のタグは全文のまま。

## 毎週の予約

| キー | 内容 |
| --- | --- |
| `station` | 局（radiko の局 ID） |
| `weekday` | 曜日（放送日の曜日）。`0`〜`6` で、`0` が日曜 |
| `start` | 開始時刻（`HH:MM`）。API では `00:00`〜`23:59` で持つ（下の「曜日と開始時刻」） |
| `from` | 任意の開始日（放送日、`YYYY-MM-DD`）。これより前の放送日の放送回には当たらない。省くか空なら制限なし |
| `until` | 任意の終了日（放送日、`YYYY-MM-DD`）。これより後の放送日の放送回には当たらない（終了日の放送回には当たる）。省くか空なら制限なし。`from` より前なら断る（同じ日はよい） |

- 毎週の予約は、局・曜日・開始時刻が完全に一致する放送回に当たる。番組の API では、番組の `weekly` に、曜日 1 つにつき 1 つ並べる。
- 1 つの番組は複数の毎週の予約を持てる。同じ放送回にほかの番組の毎週の予約も当たったら、ジョブを作らずにログに矛盾として出す。

### 曜日と開始時刻

曜日は、5 時で区切った放送日の曜日で数える（[ADR 0012](adr/0012-airing-time-in-broadcast-day-time.md)）。

- Web UI は、深夜の放送回を「放送日の曜日 + 放送日の時刻（`24:00`〜`28:59`）」で出し、受け付ける。日曜 01:00 開始の放送回は、放送日が土曜なので「土 25:00」。
- 画面で `00:00`〜`04:59` を入れると、暦の曜日のつもりの取り違えを止めるため、保存しない。
- API では、`24:00`〜`28:59` を `00:00`〜`04:59` として持つ。土曜の 25:00 は `"weekday": 6, "start": "01:00"`。

### 開始日と終了日

- 開始日・終了日と比べるのも、5 時で区切った放送日（例: `from` が `2026-10-14` なら、10-15 の 01:00 の放送回（放送日は 10-14）からは当たる）。
- 終了日を付けた・早めたときは、終了日より後の既存のジョブ（録音予定・録らない予定）は消える。その放送回を録りたければ 1 回の予約で足す。
- 終了日を過ぎた毎週の予約は消さずに残り、番組も無効にならない。終了日を過ぎたことは通知しない。
- 同じ枠で番組が終わり、別の番組として始まるとき（改称・後番組）は、古い番組の毎週の予約に終了日（最終回の放送日）、新しい番組の毎週の予約に開始日（初回の放送日）を付ける。矛盾にならずに両方の放送回が録られる（[ADR 0029](adr/0029-weekly-until-over-title-based-handover.md)）。

### 今日より前の放送日

今日より前の放送日での当たり方は、開始日の有無で変わる（[ADR 0018](adr/0018-weekly-from-reaches-past-days.md)）。

- 開始日を持たない毎週の予約は、今日から先の放送日にだけ当たる。今日より前の放送日では、その予約からジョブを新しく作らない（すでにある録音予定のジョブはそのまま録音する）。先週の放送回も録りたければ、番組表から 1 回の予約で足す。
- 開始日を持つ毎週の予約は、今日より前でも開始日からの放送日の放送回に当たり、録音期限の内側の放送回のジョブを作る。
- 番組表の過去の放送回から「毎週録音」したとき（開始日にその放送日が入る）、編集画面で開始日を過去にしたとき、無効な番組を有効に戻したときも同じ。

## 番組名の確かめ

毎週の予約は局・曜日・開始時刻だけを見るので、いつもと同じ開始時刻で始まる特番も当たる。それを録らないために、番組名を確かめる（[ADR 0018](adr/0018-weekly-from-reaches-past-days.md)・[ADR 0019](adr/0019-skip-by-title-and-by-person.md)）。

- 対象は、毎週の予約だけに当たる放送回で、番組の `check_title` が `true` のとき。1 回の予約の放送回は確かめない。
- 番組表の番組名が番組の `name` で始まらなければ、その放送回は録らない（ジョブを `skipped` にする）。
- 比べ方: 番組表の番組名の末尾の印（`(N)`、`(N時台)`、` Part2` など。下の「[title](#title)」）を落とし、両方の空白を除いて大文字にそろえ（全角・半角も揃える）てから、番組表の番組名が `name` で始まっているかを見る。

いつ決めるか:

- 今日と今日から先の放送日（最初の試行の時刻の前）では、録らない予定にする。番組表の同期のたびに決め直し、番組名が直れば録音予定に戻す。
- 最初の試行の時刻を過ぎたら、その放送日の番組表を取り直して決め直す。直っていれば録音予定に戻してそのまま録り、食い違ったままなら確定して録らなかったにする。
- 番組表を取り直せなかったときは、録らない予定のまま試し直す（1 分 → 5 分 → 15 分 → 30 分、以降 30 分ごと）。取れないまま録音期限を過ぎたら、録らない予定のまま確定する。
- 今日より前の放送日（開始日を持つ毎週の予約が当たるとき）では、はじめから確定した録らなかったでジョブを作る。
- 確定した後は、同期を繰り返しても作り直さない。
- 録らない予定にした・録音予定に戻した・録らなかったにしたときは通知する（[notifications.md](notifications.md)）。

人が決めるとき:

- 人は「録る」（`rajikura record`、画面の「録る」）で録るに戻せる。録らない予定は録音予定に、録らなかったは手動再試行になる（録音期限の内側に限る）。
- 人は、試行がまだ無い録音予定のジョブを「録らない」（`rajikura skip`、画面の「録らない」）にもできる。
- 人が決めたジョブは、その後の展開で番組名によって状態を変えない（休止・番組の無効化・番組表の終了時刻などの変化は効く）。

分割番組:

- 連結する番組では、番組名の合う放送回（と 1 回の予約の放送回）だけでジョブを作る。全部食い違えば、録らない予定（今日より前の放送日なら録らなかった）のジョブを 1 つ作る。人が決めたジョブは、番組名によらず当たる放送回を全部持つ。
- 連結しない番組では、食い違う放送回も、放送回ごとの録らない予定・録らなかったのジョブになる。

## 1 回の予約

1 回の予約は、特定の放送回 1 つを局と開始時刻で指定した予約で、番組に属する。足すのは Web UI の番組表の放送回の詳細の「この回を録音」から（API は [api.md の「1 回の予約」](api.md#1-回の予約)）。番組の編集画面には 1 回の予約の一覧と消すボタンがある。 <!-- glossary-ok: 回 -->

- 保存先のフォルダ名と連結するかは、属する番組に従う。連結する番組で、毎週の予約に当たる放送回と 1 回の予約の放送回が同じ放送日にあれば、1 つのジョブに連結する。
- 過去の放送回（録音期限の内側）も足せる。足したらすぐに録りにいく（番組名は確かめない）。
- 番組表の更新でその放送回が消えた・開始時刻が変わったら、録音予定のジョブから外し、追いかけない。1 回の予約そのものは残る。
- 番組を消したら、その番組の 1 回の予約も消える。番組の名前を変えたら、新しい名前の番組に引き継ぐ。
- その放送回のジョブが `done` になったら消す（欠落ありで `done` になったときも）。ジョブと試行の記録は残る。
- `done` にならないまま録音期限を過ぎた 1 回の予約は、番組表の同期のときに消す。
- キーワードが足した 1 回の予約も、足した後は人が足したものと同じに扱う。

## キーワード

キーワード（[ADR 0014](adr/0014-keyword-adds-onces-to-shows.md)）は、番組表を探して、当たったまだ始まっていない放送回を、その番組名から決まる番組の 1 回の予約として自動で足す決まり。番組でも予約でもなく、番組の外にある（画面では「キーワードで録音」）。Web UI のナビの「キーワード」と、API（[api.md の「キーワード」](api.md#キーワード)）で作る。

| キー | 内容 | 既定 |
| --- | --- | --- |
| `words` | 語。空白（全角も）で区切った語の AND で、どの語も、番組名・出演者・説明のどれかに含まれれば当たる（語が別々の欄に当たってもよい）。キーワードを見分けるキーでもある | （必須） |
| `exclude` | 除外する語（空白で区切る）。どれか 1 つでも、3 つの欄のどれかに含まれれば外す | 空（外さない） |
| `stations` | 当てる局（radiko の局 ID）の配列。空ならエリアの全局 | `[]` |
| `enabled` | 有効か。`false` なら当てない（足した 1 回の予約は残る） | `true` |

当て方:

- 語と欄は、全角・半角、空白、大文字・小文字の違いを無視して、部分一致を見る（番組表の検索と同じ）。曜日・時間帯では絞り込まない。
- 語の形（語を正規化して重ねを除き、並べ替えたもの）が同じキーワードは 1 つだけ作れる。
- 当てるのは、まだ始まっていない、今日から 7 日先までの放送日の放送回だけ。放送済みの放送回は、人が番組表の検索の結果から「この回を録音」で拾う。 <!-- glossary-ok: 回 -->
- 当てるのは、番組表の同期のとき（起動時と 6 時間ごと）と、キーワードを作った・変えた直後。

足す先の番組:

- 番組名から末尾の印を落とした名前の番組を探し、あればそこに足し、無ければその名前で番組を作る（有効、`check_title` はオン、毎週の予約は無し）。番組を自動で作るのは [ADR 0006](adr/0006-show-name-from-radiko.md) の例外。
- 新しく作った番組の `split` は、同じ放送日に 2 つ以上の放送回を当てるなら `"join"`、それ以外は `"none"`。
- 足す先が既存の番組なら、番組の設定は変えない。`"none"` の番組が同じ放送日に 2 つ以上の放送回を当てると、パートごとに別のファイルになる（通知の本文でそう知らせる）。人が「つながない」と決めた番組を、人が見ないまま変えないため。
- 分割番組のパート: 当たった放送回の自動の組（用語集）をまとめて足す（例: `サンプル 朝の番組` と `サンプル 朝の番組 Part2`）。組の中に末尾に印のある放送回が無ければ、当たった放送回だけを足す（同じ番組名の再放送を巻き込まないため）。
- 副題が時間帯ごとに違う番組名は、副題ごとに別の番組ができる。

足さずに飛ばす場合（通知もしない）:

- 足す先が無効な番組。
- ほかの番組がその放送回をもう当てている。足す先の番組がもう当てている。
- まとめて足すパートのどれかが上に当たれば、そのまとまりを全部飛ばす。

足した後:

- 足した 1 回の予約は、人が足したものと同じに扱う（[1 回の予約](#1-回の予約)）。番組表の更新でキーワードに一致しなくなっても外さない。 <!-- glossary-ok: 回 -->
- キーワードを変えても消しても、足した 1 回の予約と作った番組は残す。
- キーワードごとに、足した放送回を記録する。記録にある放送回には、どのキーワードももう足さない（人が消した・別の番組へ移した放送回を足し直さないため）。記録はキーワードを消すと一緒に消える。
- 2 つのキーワードが同じ放送回に当たったら、先に作ったキーワードが足す。

上限:

- キーワードごとに、足した放送回のうち、まだ録音を終えていない放送回の数が `keyword_max_pending`（[settings.md](settings.md)。既定 10）に達したら、それ以上は足さない。
- 足すのは開始が早い順で、録音が終われば空きができ、次の番組表の同期で次の放送回を足す。
- パートをまとめて足すときは、パートの数だけ数える。

通知:

- 足すたびに「キーワードで録音予定」を 1 回書く。上限に達して足さなかったときは「キーワードの上限」を 1 回だけ書く（[notifications.md](notifications.md)）。

## 保存の形

保存先の命名とタグは、Jellyfin プリセット（設定の `preset`。[ADR 0002](adr/0002-jellyfin-preset-layout.md)）で決まる。保存済みのファイルのタグは、後から書き直さない。

### ファイル名と track

`split` は、連結するかと、保存のファイル名・track を決める（[ADR 0003](adr/0003-job-per-show-and-broadcast-day.md)）。

| `split` | その日の放送回 | ファイル名 | track |
| --- | --- | --- | --- |
| `"none"` | 1 つ | `番組 YYYY-MM-DD` | `MMDD` |
| `"none"` | 2 つ以上 | `番組 YYYY-MM-DD-1`・`-2`… | `MMDD`（どのパートも同じ） |
| `"join"` | 1 つ以上 | `番組 YYYY-MM-DD`（つないだ 1 ファイル） | `MMDD×10` |
| `"separate"` | 2 つ以上 | `番組 YYYY-MM-DD-1`・`-2`… | `MMDD×10+N` |
| `"separate"` | 1 つ | `番組 YYYY-MM-DD` | `MMDD×10` |

- 分割番組の track は `MMDD×10` を基にする。パートごとのファイル（`MMDD×10+N`）とつないだファイルが、同じアルバムの中で放送日の順に並ぶように。
- 分割番組でない番組のパートの track は `MMDD` のままにする（`MMDD×10+N` にすると、2 回あった日のファイルだけが、同じ年（disc）の中で年末より後ろに並ぶため）。

### title

title は放送日（`YYYY-MM-DD`。パートがあれば `YYYY-MM-DD (N)`）で、放送回の番組名が `name` と違えば、その後に空白を挟んで放送回の番組名を足す（[ADR 0007](adr/0007-airing-title-in-title-tag.md)）。番組ごとの設定は無い。

- 同じかどうかは、両方から番組名の末尾の印を落とし、全角・半角、空白、大文字・小文字をそろえたうえでの完全一致で決める。`name` で始まっていても、続きがあれば違うとみなす。
- 足す番組名は原文どおりで、末尾の印だけを落とす。
- 連結したジョブは、`name` と違う放送回の番組名を、重複を除いて開始時刻の順に ` / ` でつなぐ（`YYYY-MM-DD A特番 / B特番`）。

末尾の印として落とす形（全角・半角を問わない）:

- 括弧付きの `(N)`・`(N時台)`・`(PARTN)`。
- 時間の範囲 `N時～N時`・`N時M分～N時M分`。
- 前に空白があるときだけの `PartN`・`Part N`・`Hour.1`・丸数字 `①`〜`⑳`・`N時台`（後ろに月日 `(MM/DD)` が付いてもよい）。
- 印にしないもの: 月日 `(MM/DD)` だけで終わる番組名、空白の無い `…Part2`、番組名の途中の `Part`・`時台`。

例（`name` が `サンプル 夜の会議室`、放送日が 2026-10-17）:

| 場合 | title |
| --- | --- |
| 放送回の番組名が `name` と同じ | `2026-10-17` |
| 放送回の番組名が `サンプル 夜の会議室　年末スペシャル` | `2026-10-17 サンプル 夜の会議室　年末スペシャル` |
| パートあり（`(1)`）で、放送回の番組名が `name` と同じ | `2026-10-17 (1)` |
| パートあり（`(1)`）で、放送回の番組名が `ゲストの夜の会議室` | `2026-10-17 (1) ゲストの夜の会議室` |

### artist・comment・カバー画像

artist は番組表の出演者。連結したジョブ（放送回が 2 つ以上）の artist・comment・カバー画像は、保存する（取れた）放送回から決める。

- artist: 放送回ごとの出演者の文字列を、1 つのかたまりとして扱う。空は使わず、同じものと、ほかの放送回の文字列の先頭部分になっているものを落とし、残ったものを開始時刻の順に ` / ` でつなぐ。
  - 例（`A` は出演者、`A　ゲスト：X` はゲストが付いた書き方）: `A` と `A　ゲスト：X` なら `A　ゲスト：X`。`A` と `A` なら `A`。`A` と `B` なら `A / B`。
  - 文字列の中身は解釈しないので、ゲストが前後で違う日は `A　ゲスト：X / A　ゲスト：Y` になる。別の人の名前がたまたま先頭部分になる場合は、短い方が落ちる。
  - radiko の出演者の欄は、局ごとに区切りが違い（` / `、`, `、`、`、`／` など）、1 人ずつに分けられない。そのため、1 つのファイルの artist に局の区切りと ` / ` が混ざることがある。
- comment（放送回の説明）: 空は使わず、同じものは最初の 1 つだけ残して、開始時刻の順に空行でつなぐ。
- カバー画像: 開始時刻がいちばん早い放送回の画像。

### artist の切り詰め

artist が 250 バイトを超えるときは、文字の途中で切らずに切り詰め、末尾に `…` を付けて 250 バイト以内にする。Jellyfin が artist からフォルダ名を作り、ext4 のファイル名の上限が 255 バイトなので、超えると人物・アーティストのメタデータを作れないため。

- 切り詰めるのは m4a の artist だけで、DB・Web UI の出演者と comment は全文のまま。
- 設定の `truncate_artist` を `false` にすると、切り詰めずに全文で書く（Jellyfin を使わない人向け）。

## 既知の問題: Jellyfin で 1 つのディスクが 300 曲を超えるとき

Jellyfin プリセットの disc は放送年なので、同じ番組・同じ放送年の曲は 1 つのディスクに並ぶ。このディスクが 300 曲を超えると、Jellyfin のアルバムの画面で、ディスクの頭から数えて 301 曲目以降の曲を押すと、その曲ではなくディスクの 1 曲目が鳴る。ファイルは無事で、検索から再生すると鳴る。

- 原因は jellyfin-web のバグで、上流で報告されている（[jellyfin/jellyfin-web#5374](https://github.com/jellyfin/jellyfin-web/issues/5374)）。rajikura では直さず、disc の決まりもタグも変えない。
- 当たるのは、土日も放送する番組（1 年で 365 回）と、同じ放送日に 2 つ以上のファイルができる番組（連結しない番組）。
- 代わりの聴き方: 検索から再生する。kikidame で聴く（kikidame は disc を使わず、album と放送日で並べる。[kikidame.md](kikidame.md)）。
- disc を細かくしないのは、m4a の disc は 65535 までしか入らず年月（`202609`）を書けないのと、細かくすると今あるファイル（disc = 年）と同じアルバムで見出しが混ざるため。
