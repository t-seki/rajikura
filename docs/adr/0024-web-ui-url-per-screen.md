# Web UI は画面ごとに URL を分け、ルーティングに wouter を使う

## 決定

Web UI は、画面と、画面の中の対象（ジョブの詳細・番組の編集・放送回の詳細）ごとに URL を分け、履歴・再読み込み・直接のリンクで同じ画面が開くようにする。ルーティングには wouter を使う。

- パスは、番組表が `/`、ほかは API と同じ英語の名前にする: `/shows`・`/shows/{名前}`（番組の編集）・`/keywords`・`/jobs`・`/jobs/{id}`（ジョブの詳細）・`/notifications`・`/settings`・`/tokens`・`/tray-link`。`/notifications` と `/tray-link` は、トレイとトーストが開く（[ADR 0023](0023-windows-tray-embedded-and-linked-by-loopback.md)）。
- 番組表の状態のうち、ブラウザに覚えていないもの（放送日・検索の語・詳細を開いた放送回）はクエリに載せる: `?day=`・`?q=`・`?airing=`（放送回は局と開始時刻で指す。形は `<局 ID>_<日本時間の開始時刻 YYYYMMDDHHmmss>`、例: `TBS_20261023140000`）。今日の放送日は `day` に載せない。ブラウザに覚えているもの（局・表示・隠した局）は localStorage に置き、URL には載せない。「隠した局も表示」と、複数の選択・取り消しの帯のようなその場かぎりの状態は、どちらにも載せない。
- 画面の切り替えと、詳細（ジョブ・番組・放送回）を開く操作は履歴に積む。「戻る」で前の画面に戻り、詳細を閉じる。放送日の切り替えと検索の語は、URL を置き換えて履歴に積まない。詳細の閉じるボタン（と Esc）は、同じ画面の中で開いて積んだ詳細なら「戻る」と同じく 1 つ戻り、URL で直接開いた詳細などでは一覧の URL に置き換える（同じ URL の履歴が 2 つ並ばないように）。
- 知らないパスは番組表を開き、URL を `/` に置き換える。無いジョブ・無い番組を指す URL は、一覧を開いて URL を一覧に置き換える。前後 7 日の外の放送日は今日を開き、URL を直す。
- 番組表・キーワードの画面から番組を開くときは、`/shows/{名前}` へ移る。番組表の検索からキーワードを作るときの語の受け渡しは URL に載せず、画面の間の受け渡しにする（再読み込みすると下書きは消える）。

### 通知から画面を開く

- 通知は対象（ジョブの出来事はジョブの id、キーワードで録音予定にした・当たらない日は番組の名前）を持つ。server が `GET /api/notifications` の各件に `link`（Web UI のパス。`/jobs/{id}`・`/shows/{名前}`、キーワードの上限で止めたは種類から `/keywords`）を組み立てる。
- Web UI の通知の画面は、`link` のある行にその画面を開くリンクを置く。トレイのトーストは、押すと `link` の画面を開く。指す先の無い通知（サービスの異常・復旧・テスト通知）のトーストと、起動して最初の「未読 N 件」のトーストは、`/notifications` を開く。
- トレイは、`link` のあるトーストの開く URL に `notification=<通知の id>` のクエリを足す。開いた Web UI は、どの画面でもこのクエリを見つけたら `POST /api/notifications/{id}/read` でその 1 件を既読にして、URL からこのキーだけを消す。トレイ自身は既読にしない。通知の画面を開くと未読を全部既読にする。

## 理由

- 画面ごとの URL が無いと、「戻る」・再読み込み・ブックマークという、ブラウザが元から持つ操作がどれも使えない。ジョブや番組を指す URL は、通知から飛ぶときの土台にもなる。
- wouter は小さく、hook（`usePathname`・`useSearch`）と `navigate` で書ける。`<Link>` が `<a href>` になるので、ナビやリンクを新しいタブで開ける。経路が 10 本ほどの規模には、React Router は大きい。
- 番組表の状態のうち localStorage にあるものを URL にも載せると、どちらを先にするかを決めなければならなくなる。localStorage に無いものだけを載せれば、両方が同じ値を持つことは起きない。
- 放送日を履歴に積むと、日付を何度か送っただけで、前の画面に戻るまで「戻る」を何度も押すことになる。

## 検討した案

- React Router（v7）。定番で機能は多いが、この規模には大きく、データの読み込みなどの使わない仕組みも持ち込む。
- 自前（`history.pushState` と `popstate`）。依存は増えないが、`<a>` の修飾キーの扱いや、パスのパラメータの照合を自分で書くことになる。
- 画面だけを URL にし、詳細と番組表の状態は載せない。ジョブや番組を URL で人に渡せず、通知から飛ぶ土台にならない。
- 番組表の局・表示も URL に載せる。localStorage とどちらを先にするかの決まりが要る。

## 帰結

- 画面を足すときは、経路と、ナビの項目を足す。
- サーバの `/api/`・`/healthz`・`/metrics` は SPA より先に受けるので、画面のパスに使えない。
- 通知の `link` が指す先が今もあるかは、server では確かめない（無ければ Web UI の画面が一覧へ移す）。
