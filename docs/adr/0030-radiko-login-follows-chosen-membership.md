# radiko のログインは人が選んだ会員種別に従い、拒まれたら非会員として録る

## 決定

会員種別は、今までどおり人が設定（`membership`）で選ぶ。非会員でない会員種別では、ログイン情報（メールアドレスは設定、パスワードは秘密）を必須にし、rajikura は radiko のログインで得たセッションを付けて認証する。

- radiko のログインは、起動の後に初めて認証が要るときに行う。得たセッションはメモリにだけ持ち、radiko に拒まれたときだけログインし直す。会員種別かログイン情報を保存したら、持っているセッションを捨てる。ログアウトの API は呼ばない。
- radiko がログインを拒んだら（ログイン情報の誤り、退会など）、非会員として認証して録り続け、サービスの異常（radiko のログインの失敗）として知らせる。ログインの応答のエリアフリーの値が、選んだ会員種別と食い違うときも、同じ異常として知らせる。
- 会員種別は、保存したらすぐ効く（[ADR 0015](0015-settings-and-secrets-in-db.md) の「保存した設定はすぐ効く」に揃える）。まだ終わっていないジョブ（`waiting`・`retrying`・`skipped`・`running`）の録音期限は、新しい会員種別で付け直す。`running` のジョブは、試行が終わった後の再試行・期限の判定で、DB から読み直した録音期限を使う。

## 理由

- ログインの応答から会員種別を判定するには、どの値がタイムフリー30 を表すかを知る必要があるが、この決定のときには分かっていなかった（分かっていたのは、公開されているほかの道具が読むエリアフリーの値だけ）。人が選ぶ形なら、応答の形に依らずに 4 つの会員種別を動かせる。
- ログイン情報を変えただけ、契約が切れただけで、自分のエリアの 7 日以内の録音まで止まるのは、失うものが大きい。非会員として録れば、会員でなければ録れない放送回だけが再試行を待つ。
- ログインをし直すたびに、ほかの端末（スマホのアプリなど）のログインに影響するおそれがある（radiko の同時ログインの扱いは確かめていない）。セッションを使い回して、ログインの回数を減らす。セッションを DB に持たないのは、秘密を増やさず、バックアップにも含めないため。

## 検討した案

- ログインの応答から会員種別を判定し、設定の `membership` を無くす。人が選び間違えることは無くなるが、タイムフリー30 を表す値が分かるまで作れない。
- ログインが拒まれたら、録音の試行をすべて失敗にする。会員として録るつもりのジョブを非会員で録ることは無くなるが、ログイン情報を直すまで、非会員で録れる放送回まで止まる。
- 認証のたびにログインする。セッションを持たずに済むが、ログインの回数が増える。

## 帰結

- 選んだ会員種別が契約と違っても、radiko が拒むかエリアフリーの値が食い違うまで、rajikura は気づかない。タイムフリー30 の食い違いは、8 日目以降の放送回が録れないことで初めて分かる。
- 再起動のたびに radiko のログインを 1 回行う。
- ログインが拒まれている間に、エリアの外の局のジョブや 8 日目以降のジョブは、再試行を待ち、録音期限を過ぎれば録音できなかったになる。
