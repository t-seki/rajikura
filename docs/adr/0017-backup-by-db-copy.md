# DB を失ったときに戻す手段とマシンを移す手段は、DB の写し（バックアップ）にする

## 決定

DB を失ったときに戻す手段と、マシンを移す手段は、`serve` が動いたまま取る DB の写し（バックアップ）にする。番組や設定をファイル（TOML など）で受け渡す口は持たない。

- バックアップは、SQLite の `VACUUM INTO` で作る DB の写しで、写しの中のログインのセッションを空にしたもの。秘密の鍵（`rajikura.key`）は含めない。
- 取る口は、API（`GET /api/backup`）・CLI（`rajikura backup [-o <file>]`）・Web UI の設定の画面の「ダウンロード」の 3 つ。CLI と画面は API を呼ぶだけ。
- `serve` は、設定で取る先のフォルダ（`backup_dir`）が決まっていれば、1 時間ごとに見て、前に取ってから 24 時間が過ぎていれば自動で取り、新しいものから `backup_keep`（既定 7）個を残す。取る先が決まっていない間は自動では取らず、帯で知らせる。取れなかったことはサービスの異常として通知する。
- 戻すときは、`serve` を止め、データのフォルダの DB をバックアップで置き換えて起動する（手順だけで、戻す API や画面は作らない）。
- 番組と設定は Web UI と API（個別の口）で扱う。AI やスクリプトは、API トークンで JSON の API を呼ぶ（[ADR 0009](0009-cli-over-http.md)）。

## 理由

- 番組や設定のファイルは、DB を失ったときの戻し先にならない。1 回の予約・キーワードが足した放送回の記録・ジョブと試行の記録・秘密の値は、そうしたファイルに入らない。戻すために要るのは DB の写しで、写しがあればファイルの受け渡しは要らない。
- 番組と設定は Web UI（番組表・キーワード・設定の画面）で作れるので、初めて入れるときにもファイルを書かなくて済む（[ADR 0015](0015-settings-and-secrets-in-db.md)）。ファイルの形を持つと、番組やキーワードに項目を足すたびに、その書式と変換も直すことになる。
- DB は WAL モードなので、動いている間にファイルを写すと、最近の書き込みが落ちうる。`VACUUM INTO` なら、`serve` を止めずに一貫した写しが取れ、Windows でもコンテナでも同じ口で取れる。
- 写しに鍵を含めると、秘密を暗号化した理由（DB のファイルだけが外に出ても秘密が読まれない。[ADR 0015](0015-settings-and-secrets-in-db.md)）が崩れる。鍵は作った後に変わらないので、人が一度別の場所に写しておけば足りる。鍵が無くても、戻せないのは秘密（通知先の Webhook の URL・SMTP のパスワード・Jellyfin の API キー）だけで、Web UI で入れ直せる。
- ログインのセッションを写しから抜くのは、戻した DB で古いログインが生き返らないようにするため。パスワードと API トークンは hash で置いているので、写しに残してよい。
- 口を作っただけでは、人が取る仕組みを組むまで 1 つも取られない。Windows の人にタスク スケジューラを組ませるのは重いので、`serve` が自分で取る。PC が決まった時刻に眠っていても取り逃さないように、時刻ではなく前に取ってからの経過で決める。

## 検討した案

- 番組と設定を TOML で書き出し・読み込みする口を持つ。受け渡しの用途は Web UI と API で足り、書式を保つ手間だけが残る。DB を失ったときの戻し先にもならない。
- 番組を一括で置き換える API を持つ。番組を名前で突き合わせる仕組みを保つ理由が無い。
- バックアップの手順だけを docs に書く（`serve` を止めてデータのフォルダを写す）。止めないと一貫した写しにならず、人が手で取るまで取られない。
- バックアップに鍵を含める。戻すときに秘密を入れ直さずに済むが、写しが漏れると秘密も読まれる。
- 写しを上げて戻す API や画面を作る。動いている `serve` の下で DB を差し替えるのは難しく、戻すことはまれ。

## 帰結

- 取る先が DB と同じディスクにあると、ディスクごと失ったときには戻せない。取る先は人が別のディスクに決める。
- 鍵を写しておかなかった人は、戻した後に秘密を入れ直す。
- 戻した後は、ログインし直す。
- 写しを取ってから戻すまでの間の変更（番組・録音の記録）は戻らない。マシンを移すときは、写しを取ったらすぐに移す元の `serve` を止める（両方が同じ放送回を録音しないように）。
