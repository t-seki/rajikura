# 録るもののまとまりを「番組」と呼び、その名前は radiko の番組名から写す

## 決定

録るもののまとまりを「番組」、番組が持つ、どの放送回を録るかの決まりを「予約」（毎週の予約・1 回の予約）と呼ぶ。コードの名前も揃える（`Show`、DB の `shows`、API の `/api/shows`）。

番組の名前（`name`。保存先のフォルダ名・ファイル名と `album` のタグになる）には、radiko の番組表の番組名を原文どおりに写す。

- 空白・記号・スポンサー名も残す。
- 落とすのは、番組名の末尾の印（`(1)` や `10時～11時` など）と、放送回ごとに変わる副題（`feat. …` など）だけ。
- 名前は人が決める。rajikura が番組名から作るのは、番組表から番組を作るときの名前の欄の既定と、キーワードが番組を作るとき（[ADR 0014](0014-keyword-adds-onces-to-shows.md)）の名前だけで、どちらも番組名から末尾の印を落としたもの。人は後から直せる。

radiko の番組名が変わったとき:

- スポンサーの交代や小さな改称は、`name` を新しい名前に直し、前のファイルも新しい名前に直す（いつも今の radiko の名前で 1 つのアルバムにする）。
- 出演者が替わって別の番組とみなすときは、別の番組（別のアルバム）として始める（切り替え方は [ADR 0029](0029-weekly-until-over-title-based-handover.md)）。
- どちらにするかは人が決める。

## 理由

- radiko の名前なら、番組表を見れば名前が決まる。
- 番組名の末尾の印と副題を落とす規則は番組ごとにばらばらで、rajikura が全部の番組名から自動で決めると例外が増える。
- 録るもののまとまりは、ライブラリでは 1 つのフォルダ（Jellyfin のアルバム）になり、予約が無くなっても残る。まとまりを「予約」と呼ぶと、録り終えて予約の無いまとまりが「スケジュールの無い予約」になり、実体に合わない。
- 決まりを「予約」と呼べば、画面の名詞（予約）・動詞（予約する）・放送回の状態（予約済み・予約なし）が 1 つの意味にまとまる。
- 「番組名」は radiko の番組表の欄の名前なので、放送回ごとの名前に使う。番組の名前と並べて書くときだけ「番組の名前」「放送回の番組名」と書き分ける。

## 検討した案

- rajikura が放送回の番組名から保存先の名前を必ず自動で決める。落とすものが番組ごとにばらばらで、規則にすると例外が増える。
- スポンサー名を落とした名前にする。radiko の名前から離れる。
- まとまりを「予約」、毎週と 1 回の決まりを「スケジュール」と呼ぶ。上の理由で、予約の無い「予約」が残る。
- まとまりの名前を「フォルダ名」と呼ぶ。名前を変えても保存済みのファイルは古いフォルダに残るので、「フォルダ名を変えてもフォルダは変わらない」ことになる。
- 放送回の名前を「タイトル」と呼ぶ。radiko と画面の「番組名」から離れ、title のタグ（[ADR 0007](0007-airing-title-in-title-tag.md)）とも別物になる。
- 画面のナビを「マイ番組」にする。radiko のアプリの「マイ番組」（お気に入り）と重なる。

## 帰結

- フォルダ名・ファイル名に使えない文字は、`SanitizeName`（`internal/library/library.go`）が `_` に置き換える。`album` のタグは置き換えず原文のまま。radiko の番組名に `:` や `?` が入ると、フォルダ名とタグが食い違う。
- radiko の番組名が変わったことは、番組名の食い違いとして見える（[ADR 0019](0019-skip-by-title-and-by-person.md)）。名前を直すかは人が決める。
- rajikura の番組は人が決めるまとまりで、radiko の番組表の上の番組と 1 対 1 とは限らない（番組名の違う放送回に当たる毎週の予約を 1 つの番組にまとめてもよい）。
- 放送回の状態の `planned`（録音予定）は、「予約済み」（録音済み・録らない予定も含む）より狭い、録ることになっていてまだ録り終えていない放送回だけを指す。
