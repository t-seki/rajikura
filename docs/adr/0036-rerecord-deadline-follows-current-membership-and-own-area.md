# 録音済みのジョブの録り直しは手動再試行とは別の操作にし、受け付けるかは今の会員種別と今の自分のエリアの録音期限で決める

## 決定

[ADR 0031](0031-rerecord-deadline-follows-current-membership.md) を置き換える。ADR 0031 の決定を全部ここに書き直したうえで、録り直しを受け付けるかと録り直しの試行の録音期限を、ジョブを作った時点の録音期限ではなく、今の会員種別に加えて今の自分のエリアの局一覧で計算した録音期限で決める。自分のエリアの局一覧を取れないときは、録り直しを断る。ADR 0031 が置き換えた [ADR 0025](0025-rerecord-done-job-separately-from-manual-retry.md) の決定は、ADR 0031 と同じくここに含む。

保存したファイルが壊れていた・消してしまった、録れた音がおかしかった、というときのために、録音済み（`done`）のジョブを録り直す操作「録り直し」を、手動再試行とは別に持つ。

- 入口は API `POST /api/jobs/{id}/rerecord`、CLI `rajikura rerecord <id>…`、Web UI のジョブの詳細の「録り直す」（確かめの画面を出す）。番組表からは録り直さない。
- 受け付けるのは、`done` のタイムフリーのジョブで、録音期限の内側のものだけ。ライブ録音のジョブ（放送は一度きり）と録音期限を過ぎたジョブは断る。
- 録音期限の内側かは、ジョブの DB の録音期限（`jobs.deadline`）ではなく、ジョブの放送回と、今の会員種別と、今の自分のエリアの局一覧から、録音期限の付け直しと同じ関数（`domain.ReviseJobDeadline`。[ADR 0032](0032-revise-deadlines-when-own-area-changes.md)）で計算した録音期限で決める。`done`・`expired` のジョブの録音期限は、会員種別の保存や自分のエリアの変化では付け直さない（[ADR 0030](0030-radiko-login-follows-chosen-membership.md)・ADR 0032）ので、DB の値は作った時点のままのことがある。
  - 今の自分のエリアの局一覧は、今日の放送日の、radiko が判定した今の自分のエリアの局（自分のエリアの番組表の局一覧）の集合。App と DB が覚えている自分のエリアではない。録るために自分のエリアの外から取る放送回かは、会員種別がエリアフリー・ダブルプランなら、局がこの集合に無いかで決め直す（録音の方式は変えない）。
  - 局一覧を取るのは、会員種別がエリアフリー・ダブルプランのときだけ。それ以外の会員種別では、局一覧を使わず、放送回が持つ印のまま計算する。
- 局一覧は、リクエストごとに 1 回だけ、DB のトランザクションの前に取る。取ってから受け付けるまでの間に自分のエリアが変わっても手当てはしない（受け付けたジョブは `retrying` なので、ADR 0032 の付け直しが録音期限を直す）。
- 一覧・詳細・各操作の応答の「録り直せるか」（`rerecordable`）と、受け付け（`POST /api/jobs/{id}/rerecord`）は、同じ関数（`domain.CheckRerecord`）と同じ局一覧で決める。
- エリアフリー・ダブルプランで局一覧を取れない・空のとき:
  - 受け付けは、store を呼ばずに 409 で断る（「自分のエリアの局一覧を取れないので、いまは録り直せない（後でやり直す）」の趣旨）。ジョブは `done` のまま。503 にはしない。
  - 一覧・詳細・各操作の応答は、ふだんどおり返し、`done` のタイムフリーから録ったジョブだけを「録り直せない」にする。局一覧は、そうしたジョブが応答にあるときだけ取る。Warn のログをリクエストごとに 1 行出す。
- 受け付けたら、ジョブの録音期限（`jobs.deadline`）も、判定と同じ会員種別と局一覧で計算した値に書き換える。書き換えないと、`retrying` に戻ったジョブが古い期限（もう過ぎている）ですぐに期限の判定に掛かり、チャプターの取り直しの打ち切りも古い期限で数えることになる。受け付けたときに、放送回の印（`job_airings.out_of_area`）は書き換えない。
- 受け付けたら、手動再試行と同じく `retrying`・試行回数 0・次の試行を今にする。作業用フォルダは `done` にしたときに消えているので、どの放送回も radiko から取り直す。
- 保存先が前の保存先と同じ名前なら、検証を終えた後に上書きする。違う名前になったら新しい名前で保存し、前のファイルは消さない。録れずに期限切れになったら、前のファイルと保存先の記録は前のまま残す。
- 録り直しの試行（前の保存先があるジョブの試行）が、録音期限の時点で一部の放送回しか取れていなければ、取れた分を保存せずに録音できなかった（`expired`）にする。前のファイル・保存先の記録・欠落の印は前のまま残す。前のファイルに欠落があっても同じで、欠落の数は比べない。録り直しでない試行の部分保存（[ADR 0003](0003-job-per-show-and-broadcast-day.md)）は別。
- 受け付けたこと自体は通知しない（人の操作は通知しない。[ADR 0019](0019-skip-by-title-and-by-person.md)）。録れれば録音済み（欠落があれば欠落あり）、録れなければ録音できなかったを、もう一度通知する。
- rajikura が自分で録り直す「チャプターの取り直し」は、受け付けた後の移り方と保存はこの操作と同じだが、録れなかったときと通知の扱いが違う（[ADR 0027](0027-chapters-refetched-by-rerecording.md)）。

## 理由

- 手動再試行はまとめて打たれうる。`done` を受け付けると、混じった録音済みのジョブが黙って録り直され、前のファイルが上書きされる。上書きを伴う操作だけに確かめを付けたい。
- 手動再試行は「まだ録れていないジョブを録り終える」操作で、入手物を使い回し、ライブ録音で録れた分を残している間は期限の後も受け付ける。録り直しは「録れた結果を捨てて録り直す」操作で、受け付ける条件も断る理由も重ならない。1 つにすると、状態ごとの場合分けが判定と用語の両方に広がる。
- 前の保存先だけを上書きするのは、別名の決まり（同じ名前があれば ` HHmm` を付ける）のままだと、録り直すたびに別名のファイルが増え、2 回目からは保存に失敗するため。上書きを前の保存先に限れば、ほかのジョブのファイルは別名の決まりで守られる。
- 一部しか取れなかった録り直しを保存しないのは、そのまま保存すると、前の保存先と同じ名前なら前のファイルを欠落のあるファイルで置き換えるため。録り直しは前のファイルがあるうえでの操作なので、一部しか取れなければ「録れなかった」として前のファイルを残す。
- 録音期限を今の会員種別で決めるのは、タイムフリー30 に登録した後、それ以前に録った番組を録り直したい場面があるため。DB の録音期限のままだと、放送から 8〜30 日の番組を、radiko では聴けるのに断ってしまう。
- 録音期限を今の自分のエリアの局一覧でも決めるのは、録ったときは自分のエリアの局だった放送回が、今はエリアの外の局になっていることがあるため。放送回が持つ印のままだと、今の自分のエリアでは期限を過ぎた（またはタイムフリーで聴けない）放送回を録り直せると判定し、前のファイルを上書きしうる。録音期限の付け直し（ADR 0032）と同じ関数に今の局一覧を渡せば、一覧の表示・受け付け・付け直しの録音期限が食い違わない。
- 局一覧を取れないときに断るのは、取れないまま放送回の印で判定すると、上のとおり期限を過ぎた放送回を録り直せると誤って判定しうるため。録り直しは前のファイルを上書きしうる操作なので、判定できないときは受け付けない。後でやり直せる。

## 検討した案

- 会員種別の保存のときに、`done`・`expired` のジョブの録音期限も付け直す。録り直さないジョブまで書き換えることになり、ADR 0030 の範囲（まだ終わっていないジョブ）を変えるので採らない。
- 手動再試行（`retry`）で `done` も受け付ける。口は増えないが、上の理由で採らない。
- 入手物から保存し直すだけにする。作業用フォルダは `done` で消えるので、残す仕組みを足すことになり、壊れた入手物を使い回すおそれもある。
- 前のファイルが残っていれば断る。人が先に消す手間がかかり、壊れたファイルを置き換えたい場面に合わない。
- 局一覧を取れないときは、放送回の印のままで判定する。上の理由で、期限を過ぎた放送回を録り直せると誤って判定しうるので採らない。
- 局一覧を取れないときは、503 で断る。ほかの断るわけ（ライブ録音・録音期限を過ぎた）と同じく、受け付けられない状態を表す 409 に揃えるので採らない。
- App と DB が覚えている自分のエリア（ADR 0032）で局一覧を取る。覚えているエリアは、付け直しが終わるまで radiko が判定した今のエリアと違いうる。録り直しは今のエリアで判定したいので採らない。

## 帰結

- 録り直しのたびに、radiko から音声を取り直す。
- 録り直しを受け付けるかは、ジョブの放送回と、今の会員種別と、今の自分のエリアの局一覧で決まる。チャプターの取り直し（ADR 0027）の受け付けは、従来どおり DB の録音期限で決める。
- 録り直しを受け付けると、ジョブは録音予定（再試行待ち）に戻り、番組表でも録音予定と出る。
- エリアフリー・ダブルプランでは、録音済みのジョブのある一覧・詳細の応答のたびに、自分のエリアの番組表を引く。番組表は radiko の番組表のキャッシュを通り、同じ放送日を重ねて取りにいくときは 1 回にまとまる。実機でどれだけ radiko に行くかは測っていない。
- 録り直しを受け付けても、放送回の印（`job_airings.out_of_area`）は今の自分のエリアで書き換えない。録音の方式は変わらない。
