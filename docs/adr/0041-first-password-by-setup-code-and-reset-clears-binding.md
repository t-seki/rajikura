# 初めてのパスワードはセットアップコードで決め、パスワードを戻すと紐づけも消す

## 決定

[ADR 0016](0016-first-password-by-setup-code.md) を置き換える。ADR 0016 の決定を全部ここに書き直したうえで、パスワードを戻す（`-reset-password`）ときに、IdP のログイン（[ADR 0040](0040-idp-login-by-generic-oidc.md)）の紐づけも消す。

Web UI のパスワードは、初めて Web UI を開いた人が決める。ただし、決められるのは、`serve` が作ったセットアップコードを入れた人だけにする。パスワードの hash は DB に置き、決めた後は Web UI から変えられる。

- パスワードが無い間は、`serve` は起動のたびにセットアップコードを新しく作り、データのフォルダの `setup-code.txt` に書き、ログにも出す。Web UI は、セットアップコードを入れてパスワードを決める画面だけを出す（IdP のログインも出さない）。
- パスワードが決まったら、セットアップコードのファイルを消し、コードを無効にする。
- セットアップコードを 5 回続けて間違えたら、次の起動まで受け付けない。
- パスワードを忘れたとき・IdP のログインで締め出されたときは、`serve` を `-reset-password` を付けて起動する。DB のパスワード・ログインのセッション・API トークン・紐づけを消し、セットアップコードからやり直す。IdP の設定（issuer・client id・client secret・Web UI の URL）は残す。

## 理由

- 設定ファイルや環境変数を書かずに始められるようにする（[ADR 0015](0015-settings-and-secrets-in-db.md)）。Windows のサービスでは、環境変数を渡すのも手間になる。
- 初めて開いた人がそのまま決める形には、決めるまでの間に誰でも決められてしまう懸念がある。セットアップコードは、データのフォルダかログを読める人、つまり rajikura を動かしている当人にしか分からないので、その懸念を防げる。
- 紐づけも消すのは、締め出されたときの戻し方を 1 つにし、誰に紐づいているか分からない紐づけを残さないため。IdP の設定は、それだけでは誰も通さないので残し、紐づけ直す手間を減らす。

## 検討した案

- 初めて開いた人が、そのまま決める。決めるまでの間に、ほかの人が先に決められる。
- ループバック（127.0.0.1 / ::1）からの接続のときだけ決められる。画面の無い Linux やコンテナで、別のマシンのブラウザから開くときに使えない。
- パスワードの bcrypt の hash を CLI で作り、環境変数で渡す。入口が DB のほかにもう 1 つでき（[ADR 0015](0015-settings-and-secrets-in-db.md) と同じ理由で採らない）、Web UI から変えられない。
- パスワードを戻しても紐づけを残す。戻した後に、知らない利用者が IdP のログインで入れるままになりうる。
- パスワードを戻すと IdP の設定も消す。紐づけを消せば誰も通らないので、消す理由が無い。

## 帰結

- データのフォルダかログを読める人は、パスワードが決まるまでの間、誰でもパスワードを決められる。
- パスワードを戻すと、発行済みの API トークンも全部無効になり、CLI・AI・トレイのトークンは発行し直す。IdP のログインも紐づけ直す。
