# 自分のエリアが変わったら、まだ終わっていないジョブの録音期限を、会員種別と同じ付け直しで直す

## 決定

録音期限は、ジョブの放送回の番組表のフラグ、録音の方式、会員種別、自分のエリア（局が自分のエリアの局一覧に入っているか）で決まる値として扱う。ジョブには、その値の写しを持つ。入力のうち会員種別か自分のエリアが変わったら、まだ終わっていないジョブ（`waiting`・`retrying`・`skipped`・`running`）の写しを、同じ計算で付け直す。会員種別の付け直し（[ADR 0030](0030-radiko-login-follows-chosen-membership.md)）と自分のエリアの付け直しは、1 つの処理にする。

- 最後に見た自分のエリアを DB に覚えておく。radiko の認証の応答の自分のエリアが、覚えている値と違ったら付け直す。起動の後に初めて認証したときも比べる。何も覚えていなければ、覚えるだけにする。radiko がエリア外と判定したときは、自分のエリアが変わったとは見なさない。
- 展開が触るジョブ（`waiting`・録らない予定）は、展開のたびに、その時点の自分のエリアで、タイムフリーで録れるかと録音の方式を決め直す。自分のエリアが変わったら、続けて番組表の同期を 1 回行う。
- 展開が触らないジョブ（`retrying`・`running`・録らなかった）は、録音の方式を変えず、録音期限だけを付け直す。タイムフリーから録るジョブの放送回で、今の自分のエリアからタイムフリーで聴けないものは、録音期限を放送の終了の 5 分後にする。これらのジョブは放送済みなので、録音期限はもう過ぎており、次の試行で、取れた分を保存するか録音できなかったにする。`running` のジョブは、試行が終わった後に録音期限を読み直す。
- 付け直しで録音期限が今より前になったジョブには、期限間近を通知しない。
- 自分のエリアが変わったら、そのことを通知する（前と後のエリア、付け直したジョブの数、録音期限が過ぎた値になったジョブの数）。変わるたびに 1 通。

## 理由

- 録音期限の写しを持つ代わりに、読むたびに計算することもできる。そうすると、録音期限で絞る DB の問い合わせ、自分のエリアの局一覧を手元に持つこと、試行を始めた後の録音の方式を固定すること、終わったジョブの値を固定することの手当てが要る。写しを書き直すきっかけは会員種別と自分のエリアの 2 つだけなので、1 つの付け直しにまとめるほうが小さい。
- 引っ越しは、止めて運んで新居で起動する形が多い。自分のエリアをメモリにだけ覚えると、その場面で変化に気付けない。
- 放送済みの回は、タイムフリーからライブに替えても録れない。ライブで録り始めたジョブは、録ったセグメントを抱えているので、タイムフリーに替えられない。そのため、展開が触らないジョブの録音の方式は変えない。
- 今の自分のエリアからタイムフリーで聴けない回を取りに行くと、radiko がアナウンスの音声を返して、それを録音済みにしてしまうおそれがある（t-seki/rajikura#27）。録音期限を過ぎた値にすれば、今の録音期限の仕組みで片付く。
- 期限間近は、録音期限までに手を打つための知らせなので、打つ手の無いジョブには出さない。

## 検討した案

- 録音期限の列をやめて、読むたびに計算する。写しを書き直す手間は無くなるが、上の手当てが要る。入力がさらに増えたら考え直す。
- 自分のエリアをメモリにだけ覚える。DB に書かずに済むが、再起動をまたいだ変化に気付けない。
- 今の自分のエリアからタイムフリーで聴けなくなったジョブも、録音期限だけ付け直してタイムフリーの再試行を続ける。アナウンスの音声を録音済みにするおそれが残る。
- 聴けなくなったジョブを、その場で録音できなかったにする。取れた分を保存できない。
- 通知せず、ログだけにする。回線や VPN の変更のように、人が気付いていない変化を知らせられない。

## 帰結

- 付け直したときに録っている途中だったタイムフリーの試行は、そのまま最後まで走る。
- radiko の判定が 2 つのエリアの間で行き来すると、そのたびに付け直しと通知が起こる。
- エリアフリーでない会員では、引っ越しで自分のエリアの外になった局のジョブは、特別には扱わない。自分のエリアの外の局の番組を登録したときと同じ扱いになる（t-seki/rajikura#32 で扱う）。
- 会員種別を下げて録音期限が今より前になったジョブにも、期限間近を通知しない。
