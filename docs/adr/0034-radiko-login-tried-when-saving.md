# radiko のログインは人が選んだ会員種別に従い、保存するときに試して拒まれたら保存しない。録るときに拒まれたら非会員として録る

## 決定

[ADR 0030](0030-radiko-login-follows-chosen-membership.md) を置き換える。radiko のログインを、起動の後に初めて認証が要るときだけでなく、会員種別かログイン情報を保存するときにも試し、radiko が拒んだら保存を断る。ほかの決定は ADR 0030 のまま。

会員種別は、今までどおり人が設定（`membership`）で選ぶ。非会員でない会員種別では、ログイン情報（メールアドレスは設定、パスワードは秘密）を必須にし、rajikura は radiko のログインで得たセッションを付けて認証する。

- 保存するときに radiko のログインを試すのは、保存した後の会員種別が非会員でなく、保存の中身に会員種別・`radiko.mail`・`radiko.password` のどれかが入っているときだけ。使うログイン情報は、保存の中身を当てた後の設定のもの（パスワードだけを直したら、保存してあるメールアドレスと新しいパスワード。非会員からエリアフリーに変えたら、保存してあるログイン情報）。非会員にする保存と、ほかの設定だけを変える保存では試さない。
  - radiko が拒んだら（応答が 200 でも 5xx でもない、または `radiko_session` が空。録るときの判定と同じ）、保存を断る。API は 400 で、何も当てない（DB も設定の写しも変えない）。サービスの異常は書かず、通知もしない。持っているセッション、拒まれた印、続いている異常も変えない。
  - 通信の失敗・5xx・時間切れのときは、保存する。持っているセッションを捨て、次に認証が要るときに radiko のログインをする（異常は書かない）。API の応答の `radiko_login` は `unchecked`。
  - 通ったら、保存し、そのとき得たセッションを持たせる（次の認証ではログインし直さない）。結果は録るときのログインと同じく扱い、続いている radiko のログインの失敗は復旧として閉じる。API の応答の `radiko_login` は `ok`。
  - 通ったが、応答のエリアフリーの値が選んだ会員種別と食い違うときは、断らずに保存し、セッションを持たせ、録るときと同じく異常として知らせる。API の応答の `radiko_login` は `mismatch`。
  - 保存するときの radiko のログインは、録音や番組表の認証の radiko のログインとは別に 1 回だけ行い、それらを待たせない。保存の途中に録音などが古いログイン情報でログインしても、保存した後に、保存のときに得たセッションで上書きする。待つのは radiko のログインの要求 1 回のタイムアウト（30 秒）までで、その間、ほかの設定の保存は待たされる。
- それ以外の radiko のログインは、起動の後に初めて認証が要るときに行う。得たセッションはメモリにだけ持ち、radiko に拒まれたときだけログインし直す。ログアウトの API は呼ばない。
- 録るとき（録音・番組表の認証）に radiko がログインを拒んだら（ログイン情報の誤り、退会など）、非会員として認証して録り続け、サービスの異常（radiko のログインの失敗）として知らせる。拒まれた後は、会員種別かログイン情報を保存するか、`serve` を再起動するまで、radiko のログインをし直さない（保存するときに拒まれたら保存しないので、拒まれた印も残る）。ログインの応答のエリアフリーの値が、選んだ会員種別と食い違うときも、同じ異常として知らせる。
- 会員種別は、保存したらすぐ効く（[ADR 0015](0015-settings-and-secrets-in-db.md) の「保存した設定はすぐ効く」に揃える）。まだ終わっていないジョブ（`waiting`・`retrying`・`skipped`・`running`）の録音期限は、新しい会員種別で付け直す。付け直しは、自分のエリアが変わったときの付け直しと 1 つの処理で（[ADR 0032](0032-revise-deadlines-when-own-area-changes.md)）、保存は付け直しを待たない。`running` のジョブは、試行が終わった後の再試行・期限の判定で、DB から読み直した録音期限を使う。

## 理由

- ログイン情報を間違えて保存しても、保存した人がその場で気付ける。録るときまで試さないと、次に認証が要るときに拒まれて、通知が届くまで気付かない。保存の前に外の状態を試して断るのは、保存先・バックアップの取る先に書けるかを試してから保存するのと同じ形。
- 保存するときに得たセッションを使うのは、ログインの回数を減らすため（下の、ほかの端末への影響の理由と同じ）。捨てると、保存の直後の認証でもう一度ログインする。
- 通信の失敗・5xx では保存するのは、radiko の障害の間に設定を保存できなくならないため。拒まれたかどうかは、radiko に届かなければ分からない。
- エリアフリーの値の食い違いで断らないのは、値の読み方を本物のアカウントでは確かめていないため。読み方が外れていると、正しい会員種別を保存できなくなる。
- ログインの応答から会員種別を判定するには、どの値がタイムフリー30 を表すかを知る必要があるが、ADR 0030 のときには分かっていなかった（分かっていたのは、公開されているほかの道具が読むエリアフリーの値だけ）。人が選ぶ形なら、応答の形に依らずに 4 つの会員種別を動かせる。
- ログイン情報を変えただけ、契約が切れただけで、自分のエリアの 7 日以内の録音まで止まるのは、失うものが大きい。録るときに拒まれたら非会員として録れば、会員でなければ録れない放送回だけが再試行を待つ。
- ログインをし直すたびに、ほかの端末（スマホのアプリなど）のログインに影響するおそれがある（radiko の同時ログインの扱いは確かめていない）。セッションを使い回して、ログインの回数を減らす。セッションを DB に持たないのは、秘密を増やさず、バックアップにも含めないため。

## 検討した案

- 保存するときに試し、拒まれても保存したうえで警告するだけにする。保存は止まらないが、間違ったログイン情報が残り、次の認証で拒まれて異常になる。
- 保存の直後に裏で radiko のログインを試し、異常を早く出すだけにする。画面は待たないが、保存した人はその場では分からず、通知を待つことになる。
- 通信の失敗・5xx でも保存を断る。確かめていないログイン情報は残らないが、radiko の障害の間は会員種別もログイン情報も保存できない。
- 保存するときに得たセッションを捨て、次の認証でログインし直す。持たせる手間は無いが、ログインの回数が増える。
- ログインの応答から会員種別を判定し、設定の `membership` を無くす。人が選び間違えることは無くなるが、タイムフリー30 を表す値が分かるまで作れない。
- 録るときにログインが拒まれたら、録音の試行をすべて失敗にする。会員として録るつもりのジョブを非会員で録ることは無くなるが、ログイン情報を直すまで、非会員で録れる放送回まで止まる。
- 認証のたびにログインする。セッションを持たずに済むが、ログインの回数が増える。

## 帰結

- radiko が拒んだかの判定は、本物の radiko では確かめていない。判定が外れると、正しいログイン情報でも保存できない（そのときは判定を直す。#16）。
- 会員種別かログイン情報の保存は、radiko の応答を待つ。radiko が応えないと、最大 30 秒待ち、その間はほかの設定の保存も待たされる。
- 選んだ会員種別が契約と違っても、radiko が拒むかエリアフリーの値が食い違うまで、rajikura は気づかない。タイムフリー30 の食い違いは、8 日目以降の放送回が録れないことで初めて分かる。
- 再起動のたびに radiko のログインを 1 回行う。
- 録るときにログインが拒まれている間に、エリアの外の局のジョブや 8 日目以降のジョブは、再試行を待ち、録音期限を過ぎれば録音できなかったになる。
