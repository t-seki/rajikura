# m4a への格納は ffmpeg を使わず Go で行う

## 決定

入手した ADTS（AAC）を m4a に入れる段は、既定で Go で行う（builtin）。ADTS のフレームをそのまま m4a の `mdat` に書き、サンプルの表とタグ（`ilst`）を go-mp4（github.com/abema/go-mp4、MIT）で組む。長さは、書いた m4a を読み直して `mdhd` の長さとタイムスケールから出し、`#EXTINF` の合計と比べる。

- 設定 `muxer`（`"builtin"` / `"ffmpeg"`）で、ffmpeg で格納する形（ffmpeg 版）も選べる。既定は `"builtin"`。`"builtin"` のとき、`ffmpeg`・`ffprobe` のキーは書いてあっても使わない。
- コンテナイメージには ffmpeg を入れない。コンテナで `"ffmpeg"` を使うには、自分で ffmpeg を入れる。

### HE-AAC（SBR）の扱い

ADTS のヘッダーには、コアの周波数（radiko は 24 kHz）しか書かれていない。builtin は音声をデコードしないので、タイムスケール・サンプルエントリーのサンプルレート・AudioSpecificConfig を、どれもヘッダーの値のまま（24 kHz、1 フレーム 1024）書き、SBR はデコーダーに見つけさせる（implicit signaling）。ffmpeg 版は音声を試しにデコードして SBR を見つけ、48 kHz・1 フレーム 2048 で書く。1 フレームの長さは 1024/24000 秒と 2048/48000 秒で同じなので、長さとシークは変わらない。

## 理由

- ffmpeg がしていたのは、コピーで m4a に入れ直すこと・タグと画像を書くこと・ffprobe で長さを測ることだけで、エンコードもデコードもしていない。これだけのために、使う人は ffmpeg を入れて PATH を通すかパスを書く必要があり、市販のラジオ録音ソフトから乗り換える Windows の人には、それが壁になる。
- ffmpeg を配るなら、ライセンス（ソースとビルドの仕方を一緒に出す）も抱える。子プロセスの扱い（ラッパーを止めても本体が残る、stderr の扱い）も消える。
- 試作で radiko の実物の録音から ffmpeg 版と builtin の両方を作って比べ、ffprobe で読める中身（長さ・タグ・カバー画像）と音声のパケット（中身のハッシュ・時刻・長さ）が全部一致した。Android の再生の部品・Jellyfin・Windows のプロパティとメディアプレーヤーでも、表示と再生とシークが同じだった。試した読み手は、どれも 24 kHz の形を ffmpeg 版と同じに扱った。
- 同じ試作で、builtin の格納は ffmpeg 版より 2 桁ほど速かった。

## 検討した案

- ffmpeg を残し、入れる手間を消す（初めて起動したときに取ってくる、インストーラーに同梱する）。書くコードは少ないが、取ってくる先を信用するかの問題、80 MB ほどの大きさ、ライセンスの表記とソースの扱い、子プロセスの面倒が残る。
- Eyevinn/mp4ff で書く。ADTS を読む部品はあるが、主な対象が fragmented MP4 で、普通の m4a は自分で組む部分が残る。go-mp4 は箱を 1 つずつ書けて、iTunes 形式のタグの箱も定義されている。
- HE-AAC かどうかを推測して、ffmpeg と同じ 48 kHz で書く。ffmpeg 版と箱の値まで一致するが、経験則が外れると事実と違う値を書き、radiko 以外の音声でも当たるかを毎回考える必要がある。
- 毎回両方で作って比べる。ffmpeg 版の時間が毎回かかる。パケットの一致は試作で確かめた。

## 帰結

- builtin が m4a を作れなかったら（ADTS が読めない、途中で周波数が変わるなど）、ffmpeg 版と同じく保存の段階の失敗として再試行する。自動で ffmpeg 版に切り替えない。
- ffmpeg 版で録ったファイル（タイムスケール 48000）と builtin のファイル（24000）で、箱の値が混ざる。表示と再生には効かない。rajikura のコードはサンプルレートを読まない。
- ffmpeg と ffprobe は寛容に読むので、それで一致しても足りない（試作では、`esds` の記述子の大きさの誤りを ffprobe が見逃し、Android で見つかった）。テストで、ffmpeg 版と箱のバイト列を比べる（違ってよい所だけを除く）。
- radiko のタイムフリーの音声は、HLS のセグメントごとに先頭に ID3v2.4 のタグを持ち、入手はセグメントをそのままつなぐので、ストリームの途中にもタグが来る。builtin はフレームの切れ目のタグを読み飛ばす（ffmpeg の aac demuxer と同じ）。builtin を確かめるときは、入手したままの音声を使う。
- MP4 の箱の作りとタグを、自分で保守する。
