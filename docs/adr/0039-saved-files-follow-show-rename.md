# 番組の名前を変えたら、全部のジョブを今の名前に付け替え、保存したファイルは rajikura が今の名前へ移す

## 決定

[ADR 0006](0006-show-name-from-radiko.md) を置き換える。「番組」「予約」の語、番組の名前を radiko の番組名から写す決め方、radiko の番組名が変わったときにどうするかを人が決めることは ADR 0006 のまま。ADR 0006 から変えるのは、スポンサーの交代や小さな改称で番組の名前を直したときに、前のファイルを新しい名前に直すのを rajikura が行うこと（保存先の移し）。

名前を変えたとき:

- 古い名前の全部のジョブ（録音済み（`done`）も含む）の番組の名前を、新しい名前に付け替える。
- 保存先のあるジョブ（状態によらない。録り直しを待つものと、録り直しが録れずに期限切れになったものも含む）と、録音中（`running`）のジョブ（最初の録音で、まだ保存先が無いものも含む）に、保存先の移しの頼みを付ける。
- 録音中のジョブの試行は、拾ったときの古い名前で保存先を組んで保存する。保存した後に、残っている頼みで録音のループが新しい名前へ移す。保存のときに引く番組の設定（分割番組の扱い）は、拾ったときの名前ではなく、DB にある今のジョブの番組の名前で引く。
- 頼みは DB に書き、録音のループが 1 件ずつ移す（保存先のファイルを書く者を録音のループ 1 つに保つ。[ADR 0038](0038-chapter-write-not-made-worse-by-transient-failure.md)）。
- 人の操作なので通知しない。

保存先の移し:

- 移し先は、保存先のパスのうち、番組のフォルダ名と、ファイル名の先頭の番組の名前だけを、移すときのジョブの番組の名前（フォルダ名・ファイル名に整えたもの）に置き換えたもの。局のフォルダ・日付・パートの番号・別名の ` HHmm` はそのまま。保存先のパスがこの形でなければ移さない。
- ファイルの `album` のタグを今の番組の名前に書き換える。ほかのタグ（`title` の放送回の番組名を含む）・画像・チャプターはファイルのまま残す。書き換えはチャプターの書き込みと同じく、同じフォルダの partial に書き、音声のサンプルが元と一致することを確かめてから置く。`muxer` の `builtin` と `ffmpeg` の両方で行う。
- 移し先に同じ名前のファイルがあれば、移さない。どちらのファイルも消さず、上書きもしない。
- 保存先にファイルが無ければ、移さない。保存先の記録は変えない。
- 移したら、保存先の記録を移し先に付け替え、メディアサーバーに再スキャンを頼む。
- 移した結果、古いフォルダに残るのが `folder.jpg` だけになったら、`folder.jpg` を新しいフォルダへ移し（新しいフォルダにもう `folder.jpg` があれば古い方を消し）、空になった古いフォルダを消す。ほかのファイルが残っていれば、古いフォルダには触らない。
- 移しの間も、ジョブの状態・試行回数・欠落の印は変えず、試行を起こさない。
- 移しのたびに、ジョブの保存先の移しの履歴に 1 行残す（時刻、移す前と移した後のパス、結果（移した、移し先にファイルがある、保存先にファイルが無い、保存先のパスが番組の名前の形でない、失敗の理由））。ジョブの画面・API・CLI に出す。通知はしない。

人が頼む保存先の移し:

- 入口は API・CLI・Web UI のジョブの画面。ジョブ 1 件ずつ頼む。
- 移し先の番組は、既定ではジョブの今の番組。今ある番組を指定でき、指定するとジョブの番組の名前をその番組に付け替えてから移す。無い番組は断る。
- 受け付けるのは保存先のあるジョブだけ。録音中（`running`）のジョブは断る（人は録音が終わってから頼む。名前の変更が付ける頼みは、上のとおり録音中のジョブにも付き、保存した後に移す）。
- 止まった移し（移し先にファイルがある、など）を、人が片付けた後にやり直すときにも使う。

## 理由

- ADR 0006 は、別の番組とみなすときは名前を変えずに別の番組を作ると決めている。名前を変えるのは、いつも同じアルバムのまま名前を直す場面なので、前のファイルも今の名前に揃うのが望ましい。
- 前のファイルを人が直す形では、rajikura は人が動かしたことを知らない。2026-11 の実機で、名前を変えた後に人が動かしたジョブを録り直したら、保存は古い名前の組み立てで行われ、古い名前のフォルダを作り直した。その後のチャプターの入れ直しも古い方に書き、同じ放送回が 2 つのアルバムに分かれた（#63）。動かす者を rajikura 1 つにすれば、ジョブの記録とファイルの場所がずれない。
- 録音済みのジョブを古い名前のまま残すと、どの番組にも当たらないジョブになり、録り直しが番組の設定（分割番組）を引けない。展開は既にあるジョブを番組の名前で照らすので、今日の放送日などの録音済みのジョブが新しい名前の番組から見つからず、同じ放送回のジョブがもう 1 つできうる。
- 移し先の組み方で番組の名前の部分だけを置き換えるのは、変えたのが番組の名前だけだから。局の名前の変化まで巻き込むと、移す範囲が広がる。
- `album` のタグを直すのは、Jellyfin が `album` のタグでアルバムを分けうるため。フォルダだけを動かしても、タグが古い名前なら 2 つのアルバムに並びうる。`title` などほかのタグを付け直さないのは、ADR 0038 と同じく、番組表の値が録ったときから変わりうるため。
- 移し先に同じ名前のファイルがあるときに止まるのは、どちらが正しいファイルかを rajikura が決めて消すと、取り返しがつかないため。
- 録り直しを待つジョブのファイルも先に移すのは、その後の録り直しが、新しいパスを前の保存先として上書きできるため（[ADR 0036](0036-rerecord-deadline-follows-current-membership-and-own-area.md) の、名前が違えば前のファイルを消さない決まりで、古いフォルダに取り残しが出ない）。
- 移しの履歴を持つのは、移しがパスを変えるので、いつ・どこへ移したかを後から確かめられるようにするため。
- 人が頼む移しを持つのは、止まった移しのやり直しと、名前を変える前に古い名前のまま残ったジョブ（どの番組にも当たらないジョブ）の付け直しに、ほかの手段が無いため。

## 検討した案

- 録音済みのジョブを古い名前のまま残し、前のファイルは人が直す（ADR 0006 のまま）。#63 のとおり、録り直しが古い名前のフォルダを作り直す。
- 録音済みのジョブの番組の名前だけを付け替え、ファイルは動かさない。録り直しは新しい名前で保存するが、人が手で動かしていると、同じ名前のファイルがあるので別名（` HHmm`）で保存し、ファイルが増える。
- 人が動かし、rajikura が追う（保存先にファイルが無ければ、今の名前で組んだパスを探して付け替える）。人が名前の整え方や別名まで合わせないと見つからず、動かす手間も人に残る。
- 前のファイルを古いフォルダのまま残し、2 つのアルバムを認める。ADR 0006 の、いつも今の radiko の名前で 1 つのアルバムにする考えから離れる。
- 移し先に音声の同じファイルがあれば、人が動かした写しとみなして付け替え、古い方を消す。どちらが正しいかを rajikura が決めることになる。
- 移し先を今の番組・局の名前で組み直す。局の名前が変わっていれば、局のフォルダまで動く。
- 録音中のジョブは、保存のときに DB から今の名前を読み直して、新しい名前で保存先を組む。保存の組み立てに名前の変更の扱いを持ち込まず、保存した後の移しに任せた。
- 移しの履歴を持たず、失敗だけをログに出す。いつ・どこへ移したかを、ジョブの画面で確かめられない。
- 古いフォルダに触らない。`folder.jpg` だけのフォルダが残り、空のアルバムに見えうる。

## 帰結

- 名前を変えた後、録音のループが移し終えるまでは、録音済みのジョブの保存先が古いフォルダのまま出る。
- 名前を変えた時点で録音中だったジョブ（最初の録音も録り直しも）は、いったん古い名前のフォルダに保存し（録り直しなら前のファイルを上書きし）、その後の移しで新しい名前のフォルダへ移る。移し終えると、ファイルは新しい名前のフォルダに 1 つだけ残り、古いフォルダは片付く（`folder.jpg` のほかに残ったファイルが無ければ）。移し終えるまでの間は、古い名前のフォルダに置かれ、`album` のタグも古い名前のまま。
- 移したファイルは、メディアサーバーからは別のファイルに見える。再生の記録などがパスで結ばれていれば、引き継がれないことがある（確かめていない）。
- この決定より前に名前を変えて、古い名前のまま残ったジョブは、人が保存先の移しを頼むまで古い名前のまま。手当ての手順は docs に書く。
