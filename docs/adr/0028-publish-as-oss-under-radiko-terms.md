# radiko の規約の第 4 条を承知で、ソースを公開した OSS として配る

## 決定

rajikura のソースを GitHub で公開した OSS（MIT）として配る。rajikura は、radiko の公式のアプリを使わずに聴き、デコードする道具で、それを第三者に配ることになる。radiko のユーザー規約（2025-10-01 改定）は、私的使用（著作権法 30 条）の範囲で使うことを認める（第 3 条(3)）一方で、公式のアプリのほかの方法で聴くこと（第 4 条(3)）、デコードすること（第 4 条(5)）、規約の条件の外で使えるようにする技術を開発し、第三者に公開・提供すること（第 4 条(7)）を禁じている。文面どおりに読めば、自分で使うことも、公開することも、これに当たりうる。それを承知で公開する。

その立場から外れないように、次を守る。

- 私的利用に限ることを README に書く。録音を共有・再配布しない
- 営利をしない。広告もライセンスの販売もせず、カンパも受けない（始めるなら、弁護士への相談を前提に決め直す）
- エリアを偽装しない。エリアの外の局は、会員のエリアフリーの正規のログインでだけ取る
- 暗号を解いて録らない。らじる★らじるの聴き逃し（HLS の AES-128）は作らない

## 理由

- 同じ種類の道具がソースを公開したまま年単位で残っている（yyoshiki41/radigo、uru2/rec_radiko_ts、yt-dlp の radiko の extractor。この決定のときに公開中であることを確かめた。radiko が削除を求めた記録があるかは確かめていない）。これを拠り所にし、その立場から外れないことを守る。
- 暗号を解く複製は、私的複製の例外から外れるおそれがある。NHK の番組は、radiko のライブ録音で暗号を解かずに録れる（[ADR 0022](0022-live-recording-for-timefree-excluded-airings.md)）。

## 検討した案

- 公開しない（自分用のまま）。第 4 条(7) の論点は避けられるが、他人に使ってもらうこと、コードを見せること、public の repo で GitHub-hosted の runner を無料で使うことを、どれも諦める。
- 弁護士に相談してから決める。営利をしない限り、相談の費用に見合わないと見た。収益化（カンパを含む）を始めるときの前提にする。
- ソースを非公開にして、バイナリを自分のサイトで配る。第 4 条(7) の「提供」には変わらず当たりうるうえ、拠り所にした公開例（どれもソースを公開している）から外れ、法人が売る市販品に近く見える。使う人も中身を確かめられない。

## 帰結

- radiko の仕様が変わると録れなくなることがあり、直す時期は約束しない（README に書く）。
- 他人が issue とコメントを書ける。作業の指示として読むのは作者が書いたものだけにし、他人の issue は作者が立て直してから扱う（[CONTRIBUTING.md](../../CONTRIBUTING.md)）。
- 案内のサイトを作るときも、ダウンロードは GitHub Release に向ける。
