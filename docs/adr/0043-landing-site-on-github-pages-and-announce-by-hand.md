# 案内のサイトをこの repo の GitHub Pages に置き、X ではリリースのときに作者が手で告知するだけにする

## 決定

- 案内のサイトを、この repo の GitHub Pages（github.io。https://t-seki.github.io/rajikura/）に置く。
- X では、リリースのときに 1 回ずつ作者が手で告知するだけにする。定期的な宣伝と、workflow からの自動の投稿はしない。
- 案内のサイトの看板（title・説明・頭の見出し・OGP）に radiko の名前を使わず、ラジオ番組を毎週予約して録り、自分のライブラリにまとめる道具として名乗る（頭の見出しは「聴きたいラジオ番組を、自分のライブラリに。」）。radiko の名前は、本文の動かせる条件と断り書きにだけ出す。フッターに「記載の会社名・サービス名は、各社の商標または登録商標です。」を置く。
- 案内のサイトに、X とはてなブックマークの共有のボタンを置く。
  - 読んだ人が自分の判断で押すものとして扱い、作者の定期的な宣伝とは別のものとする。
  - 広まりやすくはなるので、ページの下（入れ方の後）に控えめに置く。ヘッダには GitHub のアイコンだけを置く。
  - 各サービスの共有用の URL へのただのリンクにし、公式のボタンの部品やスクリプトは読み込まない（見た人の情報を各共有サービスへ送らない）。
- 案内のサイトの書体（BIZ UDPGothic）は Google Fonts から読み込む。ページを開くと、見た人の IP アドレスなどが Google に送られる。アクセス解析と外のスクリプトは読み込まない。

## 理由

- [ADR 0028](0028-publish-as-oss-under-radiko-terms.md) の立場（ソースを公開した OSS として GitHub にあり、ひっそり公開されている同じ種類の道具から外れない）から外れないため。自分のドメインで出すと個人が運営するサイトに近づき、定期的な宣伝は利用者を広く集めることになり、radiko の目に留まりやすくなる。
- 自動の投稿は、X の API が有料で、トークンの管理も要る。リリースのときの告知は手で足りる。
- radiko は他社のサービスの名前（商標）で、看板に使うと「radiko のダウンロードソフト」と見られる。そう見られたくないので、看板から外し、条件と断り書きでだけ触れる。
- 共有のボタンは、読んだ人が自分の判断で押すもので、作者が利用者を集めに行くことにならない。広まりやすくなる分は、置き場所を下に絞ることで抑える。公式の部品は読み込むと見た人の情報が各サービスへ送られるので、ただのリンクにする。
- 書体を Google Fonts から読み込むのは、案内のサイトの見た目を作り直すときに、owner が外の読み込みの縛りを外し（ダークモードに合わせることとスマホの幅で崩れないことだけを残した）、選んだデザインの書体が BIZ UDPGothic だったため。

## 検討した案

- 自分のドメインのサブドメインに置く。後から CNAME を足して移せるので、最初は github.io にした。
- X で定期的に宣伝する。利用者を広く集めることになる。
- リリースの workflow から X へ自動で投稿する。X の API が有料で、トークンの管理も要る。
- 共有のボタンに、各サービスの公式の部品を使う。見た人の情報が外に送られるので、ただのリンクにした。
- 書体を自前で置く（BIZ UDPGothic は SIL Open Font License）。Google へ送られなくなるが、日本語の書体のファイルは大きく、使う字だけに絞る仕組みが要る。

## 帰結

- 自分のドメインへ移すときと、定期的な宣伝を始めるときは、この ADR を決め直す。
- 機能を足す・変える・やめるときは、案内のサイト（`site/index.html`）の売りの文も見て直す（[development.md](../development.md#足したら直す列挙)）。
- README の冒頭・docs・GitHub の説明欄の名乗りを、案内のサイトの名乗りに揃えるかは、決めていない。揃えるときは決め直す。
- 見た人の情報を Google に送らないようにするときは、書体を自前で置くか、OS の書体に戻す。そのときは、外の読み込みの検査（#155）の許す範囲も直す。
- repo の Website の欄に案内のサイトの URL を入れるのは、repo の設定なので owner が行う。
