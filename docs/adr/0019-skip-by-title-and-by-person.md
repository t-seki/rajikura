# 今日から先の放送回も番組名で録らない予定にし、人も録る・録らないを決められるようにする

## 決定

毎週の予約は局・曜日・開始時刻だけで当たるので、特番がいつもの回と同じ開始時刻で始まると、それも録ってしまう。今日より前の放送回は、番組名が食い違えば録らなかった（`skipped`）にする（[ADR 0018](0018-weekly-from-reaches-past-days.md)）。今日から先の放送回も番組名で録らない予定にし、人の操作も持つ。

- 今日から先の放送回でも、毎週の予約だけに当たる放送回の番組名が番組の名前で始まらなければ（番組の `check_title` がオンのとき）、rajikura が録らない予定にする。1 回の予約に当たる放送回は確かめない。
- 放送の前は、番組表の同期と番組を変えた直後の展開のたびに決め直す。番組名が直れば録音予定に戻す。放送の後は、最初の試行の直前に番組表を取り直してもう 1 度確かめ、そこで確定する。確定した後は録らなかったと呼ぶ。
- 人は、ジョブ単位で「録らない」（録音予定のジョブを録らない予定・録らなかったにする）と「録る」（録らない予定・録らなかったのジョブを録るに戻す）を選べる。操作は番組表の詳細・ジョブの画面・API・CLI（`skip`・`record`）に置く。人が決めたものは、その後の同期で番組名によって覆さない。休止・番組の無効化・番組表の終了時刻などの変化は、人が決めたジョブにも効かせる。
- 状態の値は増やさない。録らない予定も録らなかったも `skipped` で、確定の前か後かで呼び方を分ける。ジョブに「人が決めた」の印（真偽値の列）を持たせる。人が止めたジョブは `skipped` で印あり、人が録ると決めたジョブは `waiting` で印あり。印は一度付けたら外さない。
- 通知は rajikura が決めたときだけ出す（録らない予定にした、録音予定に戻した、放送の後に新たに録らないと決めた）。人の操作では出さない。

### 番組表を取り直せなかったときの確定

放送の後の確定で、最初の試行の時刻に番組表を取り直せなかった（ジョブの局のどれかで番組表が取れない、または空）ときは、rajikura が決めた録らない予定を確定させない。

- 録らない予定のまま残し、取れなかった局・放送日を、番組を変えた直後の展開で失敗したときと同じ試し直しに積む（[ADR 0009](0009-cli-over-http.md)）。
- 番組表が取れた展開で、番組名が直っていれば録音予定に戻して録り、食い違ったままなら確定する。取れないまま録音期限を過ぎたら、そのまま確定する（通知はしない）。
- 人が決めたジョブは、取り直さずに確定する。
- 分割番組でつなぐ番組のジョブで、展開している局にその番組の当たる放送回が無く、ジョブもその局の放送回を持たないなら、展開はそのジョブに触らない。ほかの局の放送回だけを持つ録らない予定は、その局の当たる放送回の番組名が全部食い違うときも触らない（その局の放送回を足さない）。
- 番組表が取れない間は、放送の後でも録らない予定のまま見える。確定を待っていることは通知しない（どの局の番組表も取れない状態が続けば、番組表の同期の失敗の通知が出る）。

## 理由

- 止める判断を人だけに任せると、人が毎週の番組表を見ていないと止まらない。rajikura が番組名で止めれば、人が見ていなくても止まる。
- それでも番組名の比べ方は番組の名前の前方一致なので、録りたい特番を止めることもあるし、番組名が合っていても要らない放送回もある。なので人も決められるようにする。放送の前から「録る」を押せれば、録らなかったになってから手動再試行するのを待たずに済む。
- 7 日先の番組表の番組名は放送までに変わりうる。放送の前の判定は見込みとして出し、確定は放送の後の番組表で行う。最後の同期は放送の最大 6 時間前なので、放送の前の判定だけでは確定しない。
- 番組表を取り直せないまま確定すると、放送の前の判定のまま録らなかったになり、その後に番組名が直っていても、人が「録る」を押さない限り戻らない。確定を待っても、番組表が取れるようになれば同じ結果に追いつき、タイムフリーなので録音期限の内側なら遅れて録れる。
- 状態の値を足すには `jobs` の CHECK を変える必要があり、`jobs` を子の表（`job_airings`・`attempts`）ごと作り直す migration が要る（[ADR 0026](0026-job-id-not-reused.md)）。印の列なら `ALTER TABLE ADD COLUMN` で足せる。
- 人が決めたのは「この放送回を録るか」で、「この時刻を録る」ではない。印でジョブを丸ごと固めると、休止した放送回や止めた番組の放送回を録りにいったり、延びた終了時刻を取り込めなかったりする。

## 検討した案

- rajikura だけが止め、人の操作は持たない。録りたい特番を放送の前に録るに戻せず、番組名が合っていて要らない放送回を止められない。
- 人だけが止める。人が番組表を見ていないと止まらない。
- 放送の後（最初の試行の直前）だけで決める。番組名は確定しているが、放送の前は録音予定と出て、人が気づいて「録る」を選ぶ機会が無い。
- 放送の前の同期だけで決める。最後の同期の後に番組名が直ったときに取りこぼす。
- 状態の値を足す（録らない予定、人が止めた、など）。値だけで意味が分かるが、`jobs` を作り直す migration が要る。
- 人が決めたジョブを展開が一切触らない。上の理由のとおり、押した時点の番組表に固まる。
- 番組表を取り直せなかったときは、今の判定のまま確定する。番組名が最後の同期の後に直った回を、人が気づかなければ落とす。
- 番組表を取り直せなかったときは、確定して、取り直せなかったことを通知する。通知の種類が増え、それでも戻すのは人。
- 番組表を取り直せなかったときは、録音予定に戻して録る。放送の前の判定を捨て、特番を録ってしまう問題に戻る。

## 帰結

- 分割番組でつなぐ番組では、放送の前は同期のたびに、番組名の食い違う放送回をジョブから外し、直れば戻す。人が録ると決めたジョブは、番組名によらず当たる放送回を全部持つ。
- 人が止めたジョブが休止で消え、その後に放送回が番組表に戻ると、ジョブは作り直されて rajikura の判定に戻る。人が止めたことは覚えていない。
- 人が決めた印を外して rajikura の判定に戻す操作は作らない。
- 番組名が放送の前に行き来すると、そのたびに通知が出る。重なりを防ぐ印は持たない。
