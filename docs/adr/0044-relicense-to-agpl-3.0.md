# ライセンスを MIT から AGPL-3.0 に変える

## 決定

rajikura のライセンスを MIT から AGPL-3.0 に変える。この変更を main に入れた後のソースから当て、それより前に公開したソース（v0.45.0 までのリリースと、その後に main に入れてまだリリースしていない分）は MIT のまま残る。コミットしているのは作者と Renovate（依存関係の更新）だけなので、作者の判断で変えられる。

- `LICENSE` は GNU の配る AGPL-3.0 の原文にし、Copyright の行は残す。
- コンテナのイメージのラベル `org.opencontainers.image.licenses` の SPDX は `AGPL-3.0-only` にする。`AGPL-3.0-or-later` にすると、将来の版（FSF が決めるもの）に従うことを、今のうちに白紙で認めることになる。条件を決めるのは作者でありたいので、`-only` を選んだ。`.github/workflows/release.yml` の検査も同じ値にする。
- 実行ファイルの `rajikura licenses` は、`LICENSE` から作られるので、`LICENSE` の差し替えで AGPL-3.0 を出す。

## 理由

- 他人がフォークして、有料のアプリにしたり広告を付けたりして目立つのを防ぎたい。
- 作り変えた版のソースも公開してほしい。AGPL-3.0 は、作り変えた版を配るときに、ソースの公開を義務づける。
- 責任や権利の面で心配がある。ただし、責任の面でライセンスが守るのは無保証・免責の条項までで、これは MIT にもある。AGPL-3.0 にしても、この心配はほとんど減らない（帰結を参照）。
- rajikura は `serve` で Web UI を出す。AGPL-3.0 は、作り変えた版でネット越しにサービスを提供する場合にも（第 13 条）ソースの公開を義務づけるので、改造した版を「録音してあげるサービス」として提供するフォークにも、ソースの公開が要る。

## 検討した案

- MIT のまま。作り変えた版のソースの公開を求められず、上の理由の 1 つ目・2 つ目・4 つ目に応えない。3 つ目の責任の面は、無保証・免責の条項が MIT にもあるので、AGPL-3.0 と差が無い。
- GPL-3.0。配る版には公開が掛かるが、ネット越しのサービスには義務が届かない。`serve` の Web UI を使ったサービスが抜ける。
- 非営利のライセンス。売ること・広告を付けることを禁じられるが、OSS でなくなり、OSS として配る [ADR 0028](0028-publish-as-oss-under-radiko-terms.md) の立場から外れる。

## 帰結

- この変更より前に公開したソース（v0.45.0 までのタグと、その後に main に入れた分の履歴）は MIT のまま。誰でも、GitHub に残るそのタグや履歴を MIT の条件で使い続けられる。
- 防げないことがある。
  - MIT のまま残るソースを元にしたフォークには、AGPL-3.0 は掛からない。それを元に、ソースを公開しない有料のアプリや、広告を付けたアプリを作ることは防げない。AGPL-3.0 が掛かり、作り変えた版のソースの公開を求められるのは、この変更より後のソースを元にしたものだけ（それでも、売ること・広告を付けることそのものは下のとおり禁じられない）。
  - 他人が売ること・広告を付けることそのものは禁じられない。OSS のまま禁じる方法は無い。禁じるなら非営利のライセンスにして OSS を手放すことになり、選ばなかった。
  - 責任の面でライセンスが守るのは、無保証・免責の条項まで。
  - 「rajikura」の名前を他人に使わせないことは、ライセンスでは決められない（商標の話になる）。
- radiko の規約との関係は、ライセンスでは変わらない。第 4 条を承知のうえで公開する立場と、それを守るための決まりは、[ADR 0028](0028-publish-as-oss-under-radiko-terms.md) のまま。
- 第 13 条（ネット越しに使う人にソースを示す義務）は、改造した版に掛かる。作者は自分のライセンスに縛られないので、作者の配る版に義務は無い。それでも、GNU が LICENSE の "How to Apply These Terms" で、ネット越しに使えるソフトにはソースを得る道（画面の "Source" のリンクなど）を用意するよう勧めているので、Web UI に GitHub のリポジトリ（https://github.com/t-seki/rajikura）へのリンク（ソースへのリンク）を置いた（#176）。ログインした後はヘッダーの右上に、ログインする前の画面（ログインの画面と初期設定の画面）では画面の右上に、同じ GitHub のアイコンで出す。版の番号は、今までどおりログインした後だけに出す。改造した版を提供するフォークも、そのリンクを自分のソースへ向ければ第 13 条を満たしやすい。`rajikura licenses` は AGPL-3.0 の全文と依存のライセンスを出すだけで、ソースの置き場所は示さないので、ソースを得る道には数えない。
