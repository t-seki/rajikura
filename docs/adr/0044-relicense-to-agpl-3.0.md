# ライセンスを MIT から AGPL-3.0 に変える

## 決定

rajikura のライセンスを MIT から AGPL-3.0 に変える。これから出す版から当て、もう MIT で出した版は MIT のまま残る。コミットしているのは作者と Renovate（依存関係の更新）だけなので、作者の判断で変えられる。

- `LICENSE` は GNU の配る AGPL-3.0 の原文にし、Copyright の行は残す。
- コンテナのイメージのラベル `org.opencontainers.image.licenses` の SPDX は `AGPL-3.0-only` にする。`AGPL-3.0-or-later` にすると、将来の版（FSF が決めるもの）に従うことを、今のうちに白紙で認めることになる。条件を決めるのは作者でありたいので、`-only` を選んだ。`.github/workflows/release.yml` の検査も同じ値にする。
- 実行ファイルの `rajikura licenses` は、`LICENSE` から作られるので、`LICENSE` の差し替えで AGPL-3.0 を出す。

## 理由

- 他人がフォークして、有料のアプリにしたり広告を付けたりして目立つのを防ぎたい。
- 作り変えた版のソースも公開してほしい。AGPL-3.0 は、作り変えた版を配るときに、ソースの公開を義務づける。
- 責任や権利の面で心配がある。
- rajikura は `serve` で Web UI を出す。AGPL-3.0 は、作り変えた版でネット越しにサービスを提供する場合にも（第 13 条）ソースの公開を義務づけるので、改造した版を「録音してあげるサービス」として提供するフォークにも、ソースの公開が要る。

## 検討した案

- MIT のまま。作り変えた版のソースの公開を求められず、上の理由のどれにも応えない。
- GPL-3.0。配る版には公開が掛かるが、ネット越しのサービスには義務が届かない。`serve` の Web UI を使ったサービスが抜ける。
- 非営利のライセンス。売ること・広告を付けることを禁じられるが、OSS でなくなり、OSS として配る [ADR 0028](0028-publish-as-oss-under-radiko-terms.md) の立場から外れる。

## 帰結

- もう MIT で出した版は MIT のまま。その版を受け取った人は、MIT の条件で使い続けられる。
- 防げないことがある。
  - 他人が売ること・広告を付けることそのものは禁じられない。OSS のまま禁じる方法は無い。禁じるなら非営利のライセンスにして OSS を手放すことになり、選ばなかった。
  - 責任の面でライセンスが守るのは、無保証・免責の条項まで。
  - 「rajikura」の名前を他人に使わせないことは、ライセンスでは決められない（商標の話になる）。
- radiko の規約との関係は、ライセンスでは変わらない。第 4 条を承知のうえで公開する立場と、それを守るための決まりは、[ADR 0028](0028-publish-as-oss-under-radiko-terms.md) のまま。
- 第 13 条（ネット越しに使う人にソースを示す義務）は、改造した版に掛かる。作者の配る版は改造していないので、Web UI にソースへのリンクを足さず、今ある案内で足りると判断した。案内は、README の GitHub のリポジトリへの導線と、案内のサイトのリポジトリへのリンク。`rajikura licenses` は AGPL-3.0 の全文と依存のライセンスを出すだけで、ソースの置き場所は示さないので、案内には数えない。改造した版を提供するフォークは、自分で Web UI からソースを示す。
