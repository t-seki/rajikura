rajikura の設定（保存先・通知先・会員種別など、動かし方の設定）をまとめる。用語は [GLOSSARY.md](../GLOSSARY.md) に従う。

設定のほかに、次がある。

- 起動の設定: `serve` のフラグ `-data`・`-listen`・`-allowed-hosts`。変えるには `serve` の再起動が要る（[cli.md の「起動の設定とデータのフォルダ」](cli.md#起動の設定とデータのフォルダ)）。
- 番組: 番組と毎週の予約・1 回の予約と、キーワード（[shows.md](shows.md)）。
- 通知: 設定の `notify` の中身は [notifications.md](notifications.md)。

## 設定の変え方

設定の正本は DB にある（[ADR 0015](adr/0015-settings-and-secrets-in-db.md)）。

- 人は、Web UI のナビの「設定」の画面で変える（[web-ui.md の「設定の画面と帯」](web-ui.md#設定の画面と帯)）。
- スクリプトや AI は、API トークンで `PATCH /api/settings` に、変えるキーだけを JSON で送る（[api.md の「設定」](api.md#設定)）。書いていないキーは今の値のまま残る。今の値は `GET /api/settings` で読める（秘密の値は返らない）。
- 保存したら、再起動しなくてもすぐに効く（`radiko.program_cache_mb` を除く。`membership` もすぐに効く）。
- 走っている録音は、始めたときの設定（保存先など）のまま最後まで進める（1 つのジョブのファイルが 2 か所に分かれないように）。
- 値の確かめは、書いたキーを当てた後の設定の全体に対して行う。知らないキー（綴りの誤り）・値の誤り・通知先の設定の不足が 1 つでもあれば、1 つも当てない。

`PATCH /api/settings` の本文の例。`radiko`・`notify`・`jellyfin` の下のキーは、その名前のオブジェクトの中に書く。

```json
{
  "library": "/srv/media/radio",
  "truncate_artist": true,
  "max_attempts_free": 10,
  "keyword_max_pending": 10,
  "backup_dir": "/srv/backups/rajikura",
  "backup_keep": 7,
  "muxer": "builtin",
  "ffmpeg": "",
  "ffprobe": "",
  "chapters": true,
  "radiko": {"program_cache_mb": 64},
  "notify": {"channel": "discord", "success": true, "discord_webhook": "https://discord.com/api/webhooks/..."},
  "jellyfin": {"url": "http://jellyfin:8096", "library": "ラジオ", "api_key": "..."}
}
```

## キー

| キー | 内容 | 既定 |
| --- | --- | --- |
| `library` | 保存先のルート（絶対パス）。決まるまで録音は待たされる（番組表の同期と展開は動く）。変えるときは、`serve` がフォルダを作り、書けることを確かめてから保存する（書けなければエラーにして何も当てない）。一度決めたら空にはできない | （未定） |
| `preset` | 保存先の命名とタグのプリセット。いまは `jellyfin` だけ（[shows.md の「保存の形」](shows.md#保存の形)） | `jellyfin` |
| `truncate_artist` | artist タグに書く出演者を 250 バイトに切り詰めるか。`false` なら全文で書く（[shows.md の「artist の切り詰め」](shows.md#artist-の切り詰め)） | `true` |
| `membership` | 会員種別。`free`（非会員）/ `areafree`（エリアフリー）/ `timefree30`（タイムフリー30）/ `double`（ダブルプラン）。`free` 以外なら `radiko.mail` と `radiko.password` が要り、そろっていなければエラーにする（下の [会員種別と radiko のログイン](#会員種別と-radiko-のログインmembership)） | `free` |
| `max_attempts_free` | 非会員の試行回数の上限（1 以上） | `10` |
| `keyword_max_pending` | [キーワード](shows.md#キーワード)ごとの上限（1 以上）。キーワードが足した放送回のうち、まだ録音を終えていない放送回の数がこれに達したら、それ以上は足さない | `10` |
| `backup_dir` | 自動のバックアップを取る先のフォルダ（絶対パス）。空なら自動では取らない。変えるときは、`serve` がフォルダを作り、書けることを確かめてから保存する（[backup.md の「自動のバックアップ」](backup.md#自動のバックアップ)） | 空（自動では取らない） |
| `backup_keep` | 自動のバックアップを取る先に残す数（1 以上）。新しいものから数える | `7` |
| `muxer` | m4a への格納（と長さの測定）を何で行うか。`builtin` か `ffmpeg`（下の [m4a への格納](#m4a-への格納muxer)） | `builtin` |
| `ffmpeg` / `ffprobe` | ffmpeg / ffprobe のパス（絶対パスか、PATH から探す名前だけ）。`muxer` が `builtin` なら使わない | 空（PATH の上の `ffmpeg` / `ffprobe`） |
| `chapters` | タイムフリーから録るファイルに、radiko のチャプターを入れるか（下の [チャプター](#チャプターchapters)） | `true` |
| `radiko.program_cache_mb` | 番組表のキャッシュの合計の大きさの上限（MB。1 以上）。変えたら `serve` の再起動が要る（下の [番組表のキャッシュ](#番組表のキャッシュ)） | `64` |
| `radiko.mail` | radiko のログインに使う、radiko のアカウントのメールアドレス（ログイン情報。`membership` が `free` 以外のとき要る） | 空 |
| `radiko.password` | radiko のログインに使う、radiko のアカウントのパスワード（ログイン情報。`membership` が `free` 以外のとき要る）。秘密 | 空 |
| `notify.channel` | 通知先。`discord` / `slack` / `email` / `none`（[notifications.md](notifications.md)） | `none` |
| `notify.success` | 録音済みの通知を通知先に送るか。`false` でも Web UI の履歴には残る。ほかの通知は止められない | `true` |
| `notify.discord_webhook` | 通知を送る Discord の Webhook の URL（`channel` が `discord` のとき要る）。秘密 | 空 |
| `notify.slack_webhook` | 通知を送る Slack の Incoming Webhook の URL（`channel` が `slack` のとき要る）。秘密 | 空 |
| `notify.smtp` の `host`・`port`・`username`・`from`・`to` | メールで送る SMTP のサーバー・ポート・ユーザー名・送り主・宛先（`to` は複数書ける配列）。`channel` が `email` のとき全部要る。メールアドレスは `name@example.com` の形（表示名は付けない） | 空 |
| `notify.smtp.password` | SMTP のパスワード（`channel` が `email` のとき要る）。秘密 | 空 |
| `jellyfin.url` | Jellyfin の URL。書くと、保存のたびにライブラリの再スキャンを頼む（下の [ライブラリの再スキャン](#ライブラリの再スキャンjellyfin)） | 空（頼まない） |
| `jellyfin.library` | 再スキャンするライブラリの**名前**（`url` を書いたら必須。どちらか片方だけはエラーにする） | 空 |
| `jellyfin.api_key` | Jellyfin の API キー（`url` を書いたら必須）。秘密 | 空 |

`membership` は録音期限の日数を決める。

- 放送回の録音期限は、その放送回の終了時刻が属する放送日の終わり（翌 05:00）に、会員種別の日数（非会員・エリアフリーは 7 日、タイムフリー30・ダブルプランは 30 日）を足した時刻。
- タイムフリー30 の対象外の放送回（番組表の `tsplus_in_ng` が 0 でない放送回。ダブルプランで録る自分のエリアの外の局では `tsplus_out_ng`）は、タイムフリー30・ダブルプランでも 7 日。8 日目からは録らない。
- タイムフリーの対象外の放送回（[ライブ録音](recording.md#ライブ録音)で録る）の録音期限は、会員種別によらず放送の終了の 5 分後。

保存先の局名（フォルダ名と `album_artist` のタグ）は、radiko の局名がそのまま使われ、設定では変えない（[ADR 0004](adr/0004-station-name-from-radiko.md)）。

## 秘密

秘密（用語は [GLOSSARY.md](../GLOSSARY.md)）は、`notify.discord_webhook`・`notify.slack_webhook`・`notify.smtp.password`・`jellyfin.api_key`・`radiko.password` の 5 つ。

- DB の中では暗号化し（AES-256-GCM）、鍵はデータのフォルダの `rajikura.key` に置く。
- Web UI・API は秘密の値を返さず、設定済みかどうかだけを返す。エラーにもログにも出さない。
- 秘密のキーに空の文字列を書くと消える。

鍵のファイルが無い・合わないときも、`serve` は起動を止めない。

- 復号できない秘密は未設定として扱い、秘密ごとにエラーをログに出す（「秘密を復号できない」）。設定の画面と、Web UI の上部の帯「秘密を入れ直して」でも分かる。
- 選んだ通知先の秘密が復号できない間は、通知は Web UI の履歴にだけ残る。Jellyfin の API キーなら、再スキャンを頼まない。
- 人が秘密を入れ直したときに、鍵のファイルを読み直し、使えればそれを使う（起動の後に鍵のファイルを戻したときは、戻した鍵を使う）。
- 新しい鍵を作るのは、鍵のファイルが無いときと、中身が鍵として読めないときだけ。権限などで鍵のファイルを読めないときは、新しい鍵を作らず、入れ直しもエラーになる。
- 使っている通知先や Jellyfin の秘密が復号できないままだと、ほかのキーを変える保存もエラーになる。その秘密も一緒に入れ直す。

## 会員種別と radiko のログイン（`membership`）

会員種別は、radiko と契約している会員種別を人が選ぶ（[ADR 0034](adr/0034-radiko-login-tried-when-saving.md)）。rajikura は radiko の応答から会員種別を決めない。

- `free` 以外なら、rajikura は radiko のログイン情報（`radiko.mail` と `radiko.password`）で radiko のログインを行い、会員として録る。
- エリアフリー（`areafree`・`double`）では、自分のエリアの外の局も録れる。
- タイムフリー30（`timefree30`・`double`）では、放送から 30 日までの放送回を録れる。
- `free` 以外なのにログイン情報がそろっていない保存（ログイン情報を消す保存を含む）は、エラーにして何も当てない。ログイン情報を消すときは、`membership` を `free` にして一緒に送る。

radiko のログインは、次のように行う。

- `serve` を起動した後に、初めて radiko の認証が要るとき（録音・番組表）に 1 回行う。得たセッションはメモリにだけ持ち、DB とバックアップには入れない。
- radiko がセッションを拒んだときだけ、radiko のログインをし直す。radiko からログアウトはしない。
- 会員種別かログイン情報を保存するときにも、保存する前に radiko のログインを 1 回試す（下の「保存するときに radiko のログインを試す」）。
- `free` にしたら、radiko のログインをしない。

保存するときに radiko のログインを試す。

- 試すのは、保存した後の `membership` が `free` でなく、保存の中身に `membership`・`radiko.mail`・`radiko.password` のどれかを書いたときだけ。ログイン情報は、書いたキーを当てた後の設定のものを使う（パスワードだけを書いたら、保存してあるメールアドレスと新しいパスワード。`free` からエリアフリーにしたら、保存してあるログイン情報）。`free` にする保存と、ほかのキーだけを書く保存では試さない。
- radiko が拒んだら、保存しない。`PATCH /api/settings` は 400 にし、1 つも当てない。radiko のログインの失敗の異常は書かず、通知もしない。持っているセッションも、拒まれた後の状態も、続いている異常もそのまま。
- 通信の失敗・radiko の 5xx・時間切れなら、保存する（応答の `radiko_login` は `unchecked`）。持っているセッションを捨て、次に認証が要るときに radiko のログインをし直す。
- 通ったら、保存し、そのとき得たセッションを持つ（応答の `radiko_login` は `ok`）。次の認証では radiko のログインをし直さない。radiko のログインの失敗の異常が続いていれば、復旧として通知する。
- 通ったが、応答のエリアフリーの値が選んだ会員種別と食い違うなら、保存し、そのセッションを持つ（応答の `radiko_login` は `mismatch`）。保存は断らず、radiko のログインの失敗として通知する。
- radiko の応答を待つのは、要求 1 回のタイムアウト（30 秒）まで。その間、ほかの設定の保存は待たされる。録音・番組表の認証は待たされない。

録っている間（録音・番組表の認証）に radiko が radiko のログインを拒んだら、非会員として録り続ける。

- 自分のエリアの 7 日以内の放送回は録れる。自分のエリアの外の局と、放送から 8 日目以降の放送回は、試行の失敗として再試行を待つ。
- サービスの異常（radiko のログインの失敗）として通知し、Web UI の上部の帯にも出す（[notifications.md](notifications.md)）。radiko のログインの応答のエリアフリーの値が、選んだ会員種別と食い違うときも同じ。
- 拒まれた後は、会員種別かログイン情報を保存するか、`serve` を再起動するまで、radiko のログインをし直さない。保存するときに拒まれたら保存しないので、拒まれた後の状態も残る（保存するときに通ったら、そのセッションを使う）。
- 会員種別を `free` にして保存したら、radiko のログインを止めたので、radiko のログインの失敗の異常を終わりにする（復旧として通知する）。
- 通信の失敗や radiko の 5xx は、拒まれたとは扱わず、一時的な失敗として、次の認証でもう一度 radiko のログインをする。
- 拒まれたかは、radiko のログインの応答が 200 でも 5xx でもないか、セッションが空かで決める（保存するときに保存を断る判定も同じ）。本物の radiko が拒むときの応答は、確かめていない。

会員種別を保存したら、再起動しなくてもすぐに効く。

- 録音期限・再試行・番組表の API が答える放送日の範囲は、そのときの会員種別から決める。
- まだ終わっていないジョブ（`waiting`・`retrying`・`skipped`・`running`）の録音期限は、新しい会員種別と、`serve` が覚えている自分のエリアで付け直す。自分のエリアが変わったときと同じ付け直しで、やり方は [recording.md の「録音期限の付け直し」](recording.md#録音期限の付け直し)にある。`done`・`expired` のジョブは付け直さない。
- 付け直しは、保存を待たずに番組表の同期と同じ順番待ちで行う（同期の途中に保存したら、同期が終わった後）。
- エリアフリー・ダブルプランでは、`serve` が覚えている自分のエリアの局一覧を radiko から取って使う。取れなければ付け直さず、後で（次に番組を変えたときや番組表の同期のときなど）やり直す。それまで録音期限は前のまま。
- 付け直す前に `serve` を止めても、次の起動のときに付け直す（起動のたびに、今の会員種別で 1 回付け直す）。

## m4a への格納（`muxer`）

入手した AAC を、再エンコードせずに m4a に入れ、タグと放送回の画像とチャプターを書き、長さを測る段を、何で行うかを選ぶ（[ADR 0013](adr/0013-builtin-m4a-muxer.md)）。

- `builtin`（既定）: rajikura の中で行う。ffmpeg / ffprobe は要らない。`ffmpeg`・`ffprobe` のキーは書いてあっても使わない。
- `ffmpeg`: ffmpeg で m4a に入れ、ffprobe で長さを測る。ffmpeg / ffprobe が要る。コンテナのイメージには ffmpeg が入っていないので、コンテナで選ぶときは、ffmpeg / ffprobe の入ったイメージを自分で作る。
- どちらでも、測った長さを全セグメントの長さの合計と比べる検証（10 秒以内）は同じ。作れなかったときも、どちらも保存の段階の失敗として再試行する（`builtin` で失敗しても、自動で `ffmpeg` には切り替えない）。
- どちらで作った m4a も、長さと再生は同じ。サンプルレートの表示は、ffprobe と Jellyfin では 48 kHz、Windows のファイルのプロパティでは 24 kHz と出る。
- 変えるのは、Web UI の設定の画面の「詳しい設定」か `PATCH /api/settings`。再起動は要らない。

`ffmpeg` を Windows で使うとき:

- ffmpeg / ffprobe を入れ、設定の `ffmpeg`・`ffprobe` に絶対パスを書く（Windows のサービスは、ログインしたユーザーの PATH で探さない）。
- パッケージマネージャーが PATH に置く中継の実行ファイル（shim）ではなく、ffmpeg の本体を指す。shim を指すと、終了のときに ffmpeg の本体が残ることがある。

## チャプター（`chapters`）

radiko がタイムフリーの番組に付けるチャプター（用語集の「チャプター」。話題・場面ごとの区切り）を、タイムフリーから録るファイルに入れる（[ADR 0027](adr/0027-chapters-refetched-by-rerecording.md)・[ADR 0033](adr/0033-chapters-written-into-saved-file.md)）。ライブ録音のファイルには入れない。

- 録る時刻は `chapters` に依らない。タイムフリーから録るジョブの最初の試行は、最後の放送回の終了 + max(局の `tf_max_delay`, 150 秒) + 2 分。
- チャプターは、保存の試行の中で放送回ごとに取る。取り先は radiko の公開の文書の無い口で、予告なく変わりうる。
- 取れなかった放送回は、その分だけチャプター無しで保存し、録音は成功にする。試行を失敗にせず、通知もしない。
- 分割番組を連結したファイルでは、パートごとに取り、ファイルの中でのそのパートの始まりだけずらしてつなぐ。取れなかったパートの分だけが無くなる。
- 題は、曲の場面は `♪ 曲名 / アーティスト`、それ以外は radiko の題。255 バイトを超える題は切り詰める。
- 形は、Nero の `chpl` と QuickTime のチャプタートラックの両方を書く。`muxer` が `ffmpeg` でも `builtin` でも同じ形になる。
- チャプターを読めるかはプレイヤーによる。Jellyfin は音楽ライブラリのチャプターを保存しないので、Jellyfin の画面では飛べない。

ジョブの詳細には、チャプターが入ったか（入った・待っている・入らなかった）と、保存したファイルへのチャプターの書き込みの履歴が出る（[web-ui.md の「ジョブの画面」](web-ui.md#ジョブの画面)）。

### チャプターの取り直し

保存のときに、チャプターがまだできていない・通信に失敗したなどで取れなかった放送回があれば、ジョブは録音済み（`done`）のままチャプターを待つ（チャプターの取り直し。[ADR 0027](adr/0027-chapters-refetched-by-rerecording.md)・[ADR 0033](adr/0033-chapters-written-into-saved-file.md)）。チャプターが空のときは待たない。 <!-- 足したら直す: ジョブの状態の移り方 -->

- 待っている間は、待っている放送回のチャプターだけを、保存から 30 分おきに見る（音声は取らない）。
- 最後の放送回の終了から 6 時間か、録音期限を過ぎたら打ち切り、チャプター無しのままにする。
- 待っていた放送回が全部取れるようになったら（打ち切りの時点で一部だけ取れるようになっていれば、そのとき 1 回）、保存した放送回のチャプターを取り直し、取れた分を、保存したファイルに書き込む。radiko から音声は取り直さない。
- 書き込みでは、チャプターだけを入れて書き直す。音声・タグ・画像はファイルのまま残し、番組表から付け直さない。`muxer` に従い、`builtin` は rajikura が読んで書き直し、`ffmpeg` は ffmpeg に書き直させる。どちらも、保存のときと同じ形のチャプターを書く。
- 書き込みは、保存したファイルと同じフォルダの一時ファイル（`*.partial.m4a`）に書き、その音声のサンプル（数とバイト列）が元のファイルと一致することを確かめてから置き換える。どこかで失敗したら一時ファイルを消し、元のファイルを残す。保存先にファイルが無ければ書かない。置き換えたら、保存のときと同じくライブラリの再スキャンを頼む。
- 分割番組を連結したファイルでは、2 つ目以降のパートのチャプターを、保存のときに記録したパートの長さだけずらす。パートの長さを記録していない（この仕組みより前に保存した）ファイルでは、番組表の放送時間（終了 − 開始）でずらすので、数秒ずれうる。
- 書き込みの間も、ジョブは録音済み（`done`）のまま。試行は起こさず、試行回数・欠落の印・保存先は変わらない。番組表にも録音予定と出ない。 <!-- 足したら直す: ジョブの状態の移り方 -->
- 書き込みのたびに、ジョブの「チャプターの書き込みの履歴」に 1 行残る（時刻、誰が、結果。書き込んだときは件数、書き込めなかったときは理由）。試行の履歴とは別。
- 取り直しは、書き込めても書き込めなくても通知しない。打ち切りも通知しない。書き込めなかったことは、ジョブの書き込みの履歴とログで確かめる（音声のサンプルが元と一致しなかったときは、ログに Error で出る）。
- 待っている間に人が録り直しをしたら、待ちを消す。
- 先にファイルを取り込んだプレイヤーが、後で同じパスのチャプター付きのファイルに置き換わったことに追いつくかは、プレイヤーによる。

`true` から `false` に変えたときは、次の保存からチャプターを取りに行かず、待っているジョブの待ちも消す。`false` から `true` に変えたときは、次の保存からチャプターを取る（`false` の間に保存したファイルには足さない）。

## 番組表のキャッシュ

`serve` は、radiko から取った番組表をメモリに持つ。番組表を取るすべての場面（番組表の同期、番組を変えた直後の展開、録音の前の取り直し、Web UI の番組表、全国の検索）が同じキャッシュを通る（[ADR 0035](adr/0035-nationwide-search-from-prefetched-station-guides.md)）。

- radiko の応答の gzip のまま持ち、使うたびに展開する（応答が gzip でなければ、gzip にして持つ）。
- 番組表の同期・番組を変えた直後の展開・録音の前の取り直し・キーワードの照合・Web UI の番組表が読むときは、最大 60 秒古い番組表が返りうる。60 秒を過ぎたら radiko に変わったかを尋ね（ETag、無ければ Last-Modified で）、変わっていれば差し替える。
- 全国の検索と、全国の番組表の取り込みが読むときは、取り直しを緩める。放送日が終わった後（その放送日の翌朝 5 時より後）に取った分は、範囲の外に出るまで radiko に尋ねない。それ以外は、取ってから 6 時間は尋ねない。
- 同じ番組表を同時に 2 回は取りにいかない（取りにいっている途中なら、その結果を待って使う）。
- 会員種別がエリアフリー・ダブルプランのあいだ、`serve` は起動の直後と 6 時間ごとに、全国の局の番組表（局ごとの日別。放送日は今日の N 日前から 7 日先まで。N は会員種別の録音期限で、エリアフリーは 7、ダブルプランは 30）を裏で取り込む（並列で 8 本まで）。会員種別をエリアフリー・ダブルプランに変えて保存したら、その場で取り込みを始める。ほかの会員種別に変えたら、取り込みを止め、全国の分（自分のエリアの局のほかの局の分）を捨てる。取り込みの量と時間は確かめていない（ADR 0035 の推定は、全国の分が gzip で 15〜38MB）。
- DB には持たない。`serve` を再起動したら空から始める（全国の分も取り直す）。
- 持つのは、放送日が今日の 30 日前から 7 日先までの分だけ（会員種別によらない）。
- 合計（gzip の大きさ）が `radiko.program_cache_mb` を超えたら、最も長く使っていないものから捨てる。小さくすると、全国の分が追い出され、取り直しが増える。
- 使用量（件数と合計の大きさ）を Info のログ「番組表のキャッシュ」に出す。

## ライブラリの再スキャン（`jellyfin`）

ライブラリを NFS などのネットワーク越しに置くと、Jellyfin のリアルタイム監視が効かず、録音したものが Jellyfin に出るのが定期スキャンまで遅れる。`jellyfin.url` を書くと、`serve` はジョブを保存するたびに（[チャプターの取り直し](#チャプターの取り直し)で保存したファイルにチャプターを書き込んだときも）、Jellyfin にライブラリの再スキャンを頼む。

- 頼むのは、`jellyfin.library` で名前を指定したライブラリだけ。名前のライブラリが見つからなければ、ログに Warn を出す。
- 保存のたびに 1 回頼む。欠落ありで保存したときも頼む。
- API キーが復号できない間は、再スキャンを頼まない。
- 1 回に待つ時間の上限は 10 秒。
- URL は、Jellyfin に直接届く形（ポート番号を含めて）で書く。
- `jellyfin.url` が空なら頼まない。

頼めなかったとき: <!-- 足したら直す: サービスの異常 -->

- 失敗・上限超過はログに Warn を出す。保存は成功のままで、頼み直さない。
- あわせて、サービスの異常（再スキャンの失敗）の始まりを通知し、Web UI の帯に出す（[notifications.md](notifications.md)）。異常が続いている間は、通知し直さない。
- 次に頼めたら、復旧を通知する。
- 異常が続いている間に `jellyfin.url` を空にした（か API キーを復号できなくなった）ときは、次の見回り（1 時間ごと）か次の保存の早いほうで、頼むのを止めたことを復旧として通知する。
- `serve` を止めたことによる取り消しは通知しない。
