# 設定

rajikura の設定（保存先・通知先・会員種別など、動かし方の設定）をまとめる。用語は [GLOSSARY.md](../GLOSSARY.md) に従う。

- [m4a への格納（`muxer`）](#m4a-への格納muxer)
- [チャプター（`chapters`）](#チャプターchapters)
- [番組表のキャッシュ](#番組表のキャッシュ)
- [ライブラリの再スキャン（`jellyfin`）](#ライブラリの再スキャンjellyfin)

設定のほかに、次がある。

- 起動の設定: `serve` のフラグ `-data`・`-listen`・`-allowed-hosts`。変えるには `serve` の再起動が要る（[cli.md の「起動の設定とデータのフォルダ」](cli.md#起動の設定とデータのフォルダ)）。
- 番組: 番組と毎週の予約・1 回の予約と、キーワード（[shows.md](shows.md)）。
- 通知: 設定の `notify` の中身は [notifications.md](notifications.md)。

## 設定の変え方

設定の正本は DB にある（[ADR 0015](adr/0015-settings-and-secrets-in-db.md)）。

- 人は、Web UI のナビの「設定」の画面で変える（[web-ui.md の「設定の画面と帯」](web-ui.md#設定の画面と帯)）。
- スクリプトや AI は、API トークンで `PATCH /api/settings` に、変えるキーだけを JSON で送る（[api.md の「設定」](api.md#設定)）。書いていないキーは今の値のまま残る。今の値は `GET /api/settings` で読める（秘密の値は返らない）。
- 保存したら、再起動しなくてもすぐに効く（`radiko.program_cache_mb` を除く）。
- 走っている録音は、始めたときの設定（保存先など）のまま最後まで進める（1 つのジョブのファイルが 2 か所に分かれないように）。
- 値の確かめは、書いたキーを当てた後の設定の全体に対して行う。知らないキー（綴りの誤り）・値の誤り・通知先の設定の不足が 1 つでもあれば、1 つも当てない。

`PATCH /api/settings` の本文の例。`radiko`・`notify`・`jellyfin` の下のキーは、その名前のオブジェクトの中に書く。

```json
{
  "library": "/srv/media/radio",
  "truncate_artist": true,
  "max_attempts_free": 10,
  "keyword_max_pending": 10,
  "backup_dir": "/srv/backups/rajikura",
  "backup_keep": 7,
  "muxer": "builtin",
  "ffmpeg": "",
  "ffprobe": "",
  "chapters": true,
  "radiko": {"program_cache_mb": 64},
  "notify": {"channel": "discord", "success": true, "discord_webhook": "https://discord.com/api/webhooks/..."},
  "jellyfin": {"url": "http://jellyfin:8096", "library": "ラジオ", "api_key": "..."}
}
```

## キー

| キー | 内容 | 既定 |
| --- | --- | --- |
| `library` | 保存先のルート（絶対パス）。決まるまで録音は待たされる（番組表の同期と展開は動く）。変えるときは、`serve` がフォルダを作り、書けることを確かめてから保存する（書けなければエラーにして何も当てない）。一度決めたら空にはできない | （未定） |
| `preset` | 保存先の命名とタグのプリセット。いまは `jellyfin` だけ（[shows.md の「保存の形」](shows.md#保存の形)） | `jellyfin` |
| `truncate_artist` | artist タグに書く出演者を 250 バイトに切り詰めるか。`false` なら全文で書く（[shows.md の「artist の切り詰め」](shows.md#artist-の切り詰め)） | `true` |
| `membership` | 会員種別。`free` / `areafree` / `timefree30` / `double`。いま動かせるのは `free` だけで、ほかの値は「未対応」としてエラーにする | `free` |
| `max_attempts_free` | 非会員の試行回数の上限（1 以上） | `10` |
| `keyword_max_pending` | [キーワード](shows.md#キーワード)ごとの上限（1 以上）。キーワードが足した放送回のうち、まだ録音を終えていない放送回の数がこれに達したら、それ以上は足さない | `10` |
| `backup_dir` | 自動のバックアップを取る先のフォルダ（絶対パス）。空なら自動では取らない。変えるときは、`serve` がフォルダを作り、書けることを確かめてから保存する（[backup.md の「自動のバックアップ」](backup.md#自動のバックアップ)） | 空（自動では取らない） |
| `backup_keep` | 自動のバックアップを取る先に残す数（1 以上）。新しいものから数える | `7` |
| `muxer` | m4a への格納（と長さの測定）を何で行うか。`builtin` か `ffmpeg`（下の [m4a への格納](#m4a-への格納muxer)） | `builtin` |
| `ffmpeg` / `ffprobe` | ffmpeg / ffprobe のパス（絶対パスか、PATH から探す名前だけ）。`muxer` が `builtin` なら使わない | 空（PATH の上の `ffmpeg` / `ffprobe`） |
| `chapters` | タイムフリーから録るファイルに、radiko のチャプターを入れるか（下の [チャプター](#チャプターchapters)） | `true` |
| `radiko.program_cache_mb` | 番組表のキャッシュの合計の大きさの上限（MB。1 以上）。変えたら `serve` の再起動が要る（下の [番組表のキャッシュ](#番組表のキャッシュ)） | `64` |
| `notify.channel` | 通知先。`discord` / `slack` / `email` / `none`（[notifications.md](notifications.md)） | `none` |
| `notify.success` | 録音済みの通知を通知先に送るか。`false` でも Web UI の履歴には残る。ほかの通知は止められない | `true` |
| `notify.discord_webhook` | 通知を送る Discord の Webhook の URL（`channel` が `discord` のとき要る）。秘密 | 空 |
| `notify.slack_webhook` | 通知を送る Slack の Incoming Webhook の URL（`channel` が `slack` のとき要る）。秘密 | 空 |
| `notify.smtp` の `host`・`port`・`username`・`from`・`to` | メールで送る SMTP のサーバー・ポート・ユーザー名・送り主・宛先（`to` は複数書ける配列）。`channel` が `email` のとき全部要る。メールアドレスは `name@example.com` の形（表示名は付けない） | 空 |
| `notify.smtp.password` | SMTP のパスワード（`channel` が `email` のとき要る）。秘密 | 空 |
| `jellyfin.url` | Jellyfin の URL。書くと、保存のたびにライブラリの再スキャンを頼む（下の [ライブラリの再スキャン](#ライブラリの再スキャンjellyfin)） | 空（頼まない） |
| `jellyfin.library` | 再スキャンするライブラリの**名前**（`url` を書いたら必須。どちらか片方だけはエラーにする） | 空 |
| `jellyfin.api_key` | Jellyfin の API キー（`url` を書いたら必須）。秘密 | 空 |

`membership` は録音期限の日数を決める。

- 放送回の録音期限は、その放送回の終了時刻が属する放送日の終わり（翌 05:00）に、会員種別の日数（非会員・エリアフリーは 7 日、タイムフリー30・ダブルプランは 30 日）を足した時刻。
- タイムフリーの対象外の放送回（[ライブ録音](recording.md#ライブ録音)で録る）の録音期限は、会員種別によらず放送の終了の 5 分後。

保存先の局名（フォルダ名と `album_artist` のタグ）は、radiko の局名がそのまま使われ、設定では変えない（[ADR 0004](adr/0004-station-name-from-radiko.md)）。

## 秘密

秘密（用語は [GLOSSARY.md](../GLOSSARY.md)）は、`notify.discord_webhook`・`notify.slack_webhook`・`notify.smtp.password`・`jellyfin.api_key` の 4 つ。

- DB の中では暗号化し（AES-256-GCM）、鍵はデータのフォルダの `rajikura.key` に置く。
- Web UI・API は秘密の値を返さず、設定済みかどうかだけを返す。エラーにもログにも出さない。
- 秘密のキーに空の文字列を書くと消える。

鍵のファイルが無い・合わないときも、`serve` は起動を止めない。

- 復号できない秘密は未設定として扱い、秘密ごとにエラーをログに出す（「秘密を復号できない」）。設定の画面と、Web UI の上部の帯「秘密を入れ直して」でも分かる。
- 選んだ通知先の秘密が復号できない間は、通知は Web UI の履歴にだけ残る。Jellyfin の API キーなら、再スキャンを頼まない。
- 人が秘密を入れ直したときに、鍵のファイルを読み直し、使えればそれを使う（起動の後に鍵のファイルを戻したときは、戻した鍵を使う）。
- 新しい鍵を作るのは、鍵のファイルが無いときと、中身が鍵として読めないときだけ。権限などで鍵のファイルを読めないときは、新しい鍵を作らず、入れ直しもエラーになる。
- 使っている通知先や Jellyfin の秘密が復号できないままだと、ほかのキーを変える保存もエラーになる。その秘密も一緒に入れ直す。

## m4a への格納（`muxer`）

入手した AAC を、再エンコードせずに m4a に入れ、タグと放送回の画像とチャプターを書き、長さを測る段を、何で行うかを選ぶ（[ADR 0013](adr/0013-builtin-m4a-muxer.md)）。

- `builtin`（既定）: rajikura の中で行う。ffmpeg / ffprobe は要らない。`ffmpeg`・`ffprobe` のキーは書いてあっても使わない。
- `ffmpeg`: ffmpeg で m4a に入れ、ffprobe で長さを測る。ffmpeg / ffprobe が要る。コンテナのイメージには ffmpeg が入っていないので、コンテナで選ぶときは、ffmpeg / ffprobe の入ったイメージを自分で作る。
- どちらでも、測った長さを全セグメントの長さの合計と比べる検証（10 秒以内）は同じ。作れなかったときも、どちらも保存の段階の失敗として再試行する（`builtin` で失敗しても、自動で `ffmpeg` には切り替えない）。
- どちらで作った m4a も、長さと再生は同じ。サンプルレートの表示は、ffprobe と Jellyfin では 48 kHz、Windows のファイルのプロパティでは 24 kHz と出る。
- 変えるのは、Web UI の設定の画面の「詳しい設定」か `PATCH /api/settings`。再起動は要らない。

`ffmpeg` を Windows で使うとき:

- ffmpeg / ffprobe を入れ、設定の `ffmpeg`・`ffprobe` に絶対パスを書く（Windows のサービスは、ログインしたユーザーの PATH で探さない）。
- パッケージマネージャーが PATH に置く中継の実行ファイル（shim）ではなく、ffmpeg の本体を指す。shim を指すと、終了のときに ffmpeg の本体が残ることがある。

## チャプター（`chapters`）

radiko がタイムフリーの番組に付けるチャプター（用語集の「チャプター」。話題・場面ごとの区切り）を、タイムフリーから録るファイルに入れる（[ADR 0027](adr/0027-chapters-refetched-by-rerecording.md)）。ライブ録音のファイルには入れない。

- 録る時刻は `chapters` に依らない。タイムフリーから録るジョブの最初の試行は、最後の放送回の終了 + max(局の `tf_max_delay`, 150 秒) + 2 分。
- チャプターは、保存の試行の中で放送回ごとに取る。取り先は radiko の公開の文書の無い口で、予告なく変わりうる。
- 取れなかった放送回は、その分だけチャプター無しで保存し、録音は成功にする。試行を失敗にせず、通知もしない。
- 分割番組を連結したファイルでは、パートごとに取り、ファイルの中でのそのパートの始まりだけずらしてつなぐ。取れなかったパートの分だけが無くなる。
- 題は、曲の場面は `♪ 曲名 / アーティスト`、それ以外は radiko の題。255 バイトを超える題は切り詰める。
- 形は、Nero の `chpl` と QuickTime のチャプタートラックの両方を書く。`muxer` が `ffmpeg` でも `builtin` でも同じ形になる。
- チャプターを読めるかはプレイヤーによる。Jellyfin は音楽ライブラリのチャプターを保存しないので、Jellyfin の画面では飛べない。

ジョブの詳細には、チャプターが入ったか（入った・待っている・入らなかった）が出る（[web-ui.md の「ジョブの画面」](web-ui.md#ジョブの画面)）。

### チャプターの取り直し

保存のときに、チャプターがまだできていない・通信に失敗したなどで取れなかった放送回があれば、ジョブは録音済み（`done`）のままチャプターを待つ（チャプターの取り直し。[ADR 0027](adr/0027-chapters-refetched-by-rerecording.md)）。チャプターが空のときは待たない。 <!-- 足したら直す: ジョブの状態の移り方 -->

- 待っている間は、待っている放送回のチャプターだけを、保存から 30 分おきに見る（音声は取らない）。
- 最後の放送回の終了から 6 時間か、録音期限を過ぎたら打ち切り、チャプター無しのままにする。
- 待っていた放送回が全部取れるようになったら（打ち切りの時点で一部だけ取れるようになっていれば、そのとき 1 回）、[録り直し](cli.md#rerecord)と同じく、どの放送回も radiko から取り直して保存する。前の保存先と同じ名前なら上書きする。
- 取り直しの試行が録れなければ、録音できなかった（`expired`）にせず、録音済み（`done`）に戻す。前のファイル、保存先、欠落の印は前のまま残る。 <!-- 足したら直す: ジョブの状態の移り方 -->
- 取り直しは、録れても録れなくても通知しない。打ち切りも通知しない。
- 待っている間に人が録り直しをしたら、待ちを消す。
- 取り直しの試行の間（数分）は、ジョブが再試行待ち・録音中になり、番組表には録音予定と出る。
- チャプターのある局では、ほぼ全部の放送回の音声を 2 回取り、ファイルを 2 回書き、再スキャンも 2 回頼む。1 回にしたいときは `chapters` を `false` にする。
- 先にファイルを取り込んだプレイヤーが、後で同じパスのチャプター付きのファイルに置き換わったことに追いつくかは、プレイヤーによる。

`true` から `false` に変えたときは、次の保存からチャプターを取りに行かず、待っているジョブの待ちも消す。`false` から `true` に変えたときは、次の保存からチャプターを取る（`false` の間に保存したファイルには足さない）。

## 番組表のキャッシュ

`serve` は、radiko から取った番組表をメモリに持つ。番組表を取るすべての場面（番組表の同期、番組を変えた直後の展開、録音の前の取り直し、Web UI の番組表）が同じキャッシュを通る。

- 有効にしている間は、最大 60 秒古い番組表が返りうる。60 秒を過ぎたら radiko に変わったかを尋ね、変わっていれば差し替える。
- DB には持たない。`serve` を再起動したら空から始める。
- 持つのは、放送日が今日の 7 日前（`timefree30`・`double` では 30 日前）から 7 日先までの分だけ。
- 合計が `radiko.program_cache_mb` を超えたら、最も長く使っていないものから捨てる。
- 使用量（件数と合計の大きさ）を Info のログ「番組表のキャッシュ」に出す。

## ライブラリの再スキャン（`jellyfin`）

ライブラリを NFS などのネットワーク越しに置くと、Jellyfin のリアルタイム監視が効かず、録音したものが Jellyfin に出るのが定期スキャンまで遅れる。`jellyfin.url` を書くと、`serve` はジョブを保存するたびに、Jellyfin にライブラリの再スキャンを頼む。

- 頼むのは、`jellyfin.library` で名前を指定したライブラリだけ。名前のライブラリが見つからなければ、ログに Warn を出す。
- 保存のたびに 1 回頼む。欠落ありで保存したときも頼む。
- API キーが復号できない間は、再スキャンを頼まない。
- 1 回に待つ時間の上限は 10 秒。
- URL は、Jellyfin に直接届く形（ポート番号を含めて）で書く。
- `jellyfin.url` が空なら頼まない。

頼めなかったとき: <!-- 足したら直す: サービスの異常 -->

- 失敗・上限超過はログに Warn を出す。保存は成功のままで、頼み直さない。
- あわせて、サービスの異常（再スキャンの失敗）の始まりを通知し、Web UI の帯に出す（[notifications.md](notifications.md)）。異常が続いている間は、通知し直さない。
- 次に頼めたら、復旧を通知する。
- 異常が続いている間に `jellyfin.url` を空にした（か API キーを復号できなくなった）ときは、次の見回り（1 時間ごと）か次の保存の早いほうで、頼むのを止めたことを復旧として通知する。
- `serve` を止めたことによる取り消しは通知しない。
