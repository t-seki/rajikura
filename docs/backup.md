# バックアップと戻し方

バックアップ（用語は [GLOSSARY.md](../GLOSSARY.md)、決定は [ADR 0017](adr/0017-backup-by-db-copy.md)）は、`serve` が動いたまま取る DB の写し。DB を失ったときに戻すのと、マシンを移すのに使う。

- [中身](#中身)
- [取り方](#取り方)
- [自動のバックアップ](#自動のバックアップ)
- [戻し方](#戻し方)
- [マシンを移す](#マシンを移す)

## 中身

- 含むもの: 番組・毎週の予約・1 回の予約・キーワードとその足した放送回の記録・設定（秘密は暗号化したまま）・ジョブと試行の記録・通知の履歴・Web UI のパスワードの hash・API トークンの hash。
- 含まないもの: ログインのセッション、秘密の鍵のファイル（`rajikura.key`）、録音したファイル（ライブラリの中身。DB の外にある）。
- `serve` は止めなくてよい。動いている間も一貫したバックアップを作る（動いている間に `rajikura.db` のファイルだけを写すと、最近の書き込みが落ちうる）。
- バックアップは、DB と別のディスクに置く（同じディスクにあると、ディスクごと失ったときに戻せない）。
- 取ってから戻すまでの間の変更（番組・録音の記録など）は戻らない。

## 取り方

人が取る口は 3 つ。`serve` が自分で取る[自動のバックアップ](#自動のバックアップ)は別。

- Web UI: ナビの「設定」の画面の「バックアップ」で「ダウンロード」を押す。ブラウザが `rajikura-<日時>.db` を保存する。 <!-- glossary-ok: ダウンロード -->
- CLI: `backup`（[cli.md の「backup」](cli.md#backup)）。`-o` を省くと、今のフォルダに `rajikura-<日時>.db` で書く。

  ```bash
  rajikura -url '<serve の URL>' -token '<発行したトークン>' backup -o rajikura-backup.db
  ```

- API: API トークンで呼ぶ（AI やスクリプトから取るとき。[api.md の「バックアップ」](api.md#バックアップ)）。

  ```bash
  curl -fsS -H 'Authorization: Bearer <発行したトークン>' -o rajikura-backup.db '<serve の URL>/api/backup'
  ```

秘密の鍵のファイル（データのフォルダの `rajikura.key`）は、一度別の場所に写しておく（任意）。

- 鍵は作った後に変わらないので、一度写せば足りる（鍵が作り直されたときは、写し直す）。
- 鍵を写しておけば、戻した後に秘密 4 つ（Discord・Slack の Webhook の URL、SMTP のパスワード、Jellyfin の API キー）を入れ直さずに済む。
- 写していなければ、戻した後に設定の画面で秘密を入れ直す（入れ直すまで「秘密を入れ直して」の帯が出る）。

## 自動のバックアップ

`serve` は、設定の `backup_dir`（取る先のフォルダ。絶対パス）があれば、人が取らなくても自動でバックアップを取る。`backup_dir` が空の間は自動では取らず、Web UI の上部に「自動のバックアップが止まっている」の帯を出す（[web-ui.md の「設定の画面と帯」](web-ui.md#設定の画面と帯)）。

- 1 時間ごとに見て、前に取れてから 24 時間が過ぎていれば取る。決まった時刻には取らないので、PC が眠っていても、起きた後の見回りで拾う。`serve` を起動した直後にも見る。
- 取ったバックアップは、`backup_dir` に `rajikura-<日時>.db`（日時は日本時間の `YYYYMMDD-HHMMSS`）で置く。途中で止まっても、この名前の不完全なファイルは残らない。
- 取れたら、`backup_dir` の中の `rajikura-<日時>.db` の形のファイルだけを、新しいものから `backup_keep`（既定 7）個残して消す。ほかのファイルやフォルダには触らない。
- 前に取れた日時は DB に持ち、設定の画面の「バックアップ」の欄に出す。取る先のファイルを手で消しても、24 時間は取り直さない。取る先を変えて保存すると忘れ、次の見回りで新しい取る先に取る。
- 取る先は、DB と別のディスクに置く。コンテナで動かすときは、取る先のフォルダもマウントする。

取れなかったとき（取る先を作れない・書けない、ディスクがいっぱいなど）: <!-- 足したら直す: サービスの異常 -->

- ログにエラーを出し、サービスの異常（バックアップの失敗）の始まりを通知し、Web UI の帯にも出す（[notifications.md](notifications.md)）。
- 続けて失敗している間は通知し直さず、1 時間後の見回りでまた取ろうとする。
- 次に取れたら復旧を通知する。取る先を空にしたときも、止めたことを復旧として通知する。

## 戻し方

戻す API と画面は無く、手で DB を置き換える。

1. `serve` を止める。
2. データのフォルダの `rajikura.db` をバックアップで置き換え、古い `rajikura.db-wal` と `rajikura.db-shm` があれば消す（置き換える前の DB のもので、置き換えた DB とは合わない）。`<データのフォルダ>` は `serve` の `-data`、`<バックアップ>` は取ったファイルのパス。

   ```bash
   cp '<バックアップ>' '<データのフォルダ>/rajikura.db'
   rm -f '<データのフォルダ>/rajikura.db-wal' '<データのフォルダ>/rajikura.db-shm'
   ```

   Windows では、エクスプローラーで同じことをする（バックアップを `rajikura.db` の名前でデータのフォルダに置き、`rajikura.db-wal` と `rajikura.db-shm` を消す）。
3. データのフォルダに鍵のファイル（`rajikura.key`）が無くなっていて、写しておいた鍵があれば、それを置く。
4. `serve` を起動し、Web UI でログインし直す（ログインのセッションは戻らない）。パスワードと API トークンは、バックアップを取ったときのものに戻る。鍵を置けなかったときは、設定の画面で秘密を入れ直す。

コンテナで動かすときは、`/data` にマウントしたフォルダがデータのフォルダになる。

## マシンを移す

Linux から Windows へなど、OS が違うマシンへも同じ手順で移す（SQLite の DB のファイルの形式は OS によらない）。

1. 録音中でないとき（ジョブの画面に録音中のジョブが無いとき）に、移す元でバックアップを取る（Web UI か CLI）。
2. すぐに移す元の `serve` を止める（両方が同じ放送回を録音しないように）。取ってから止めるまでの変更は移らない。
3. 移す先のデータのフォルダに、バックアップを `rajikura.db` として置く。鍵のファイルを写してあれば、`rajikura.key` も置く。
4. 移す先で `serve` を起動し、Web UI でログインし直して、設定の画面で次を直す。
   - 保存先（`library`）を、移す先のフォルダにする。
   - `muxer` が `ffmpeg` なら、移す先に ffmpeg / ffprobe を入れて、`ffmpeg`・`ffprobe` のパスを直す。`builtin`（既定）なら ffmpeg は要らない。
   - 鍵を置かなかったときは、秘密を入れ直す。
5. 録音したファイル（ライブラリの中身）は DB の外にあるので、要るなら別に移す。過去のジョブの保存先は、移す元のパスのまま出る（表示にだけ使う）。

ファイルに手が届くなら、代わりに、移す元の `serve` を止めてから、データのフォルダを丸ごと（`rajikura.db`・`rajikura.db-wal`・`rajikura.db-shm`・`rajikura.key` を一緒に）写してもよい。止めずに写すと、最近の書き込みが落ちうる。写した後の 4・5 は同じ。
